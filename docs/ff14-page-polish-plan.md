# FF14 查询页局部美化方案

> 2026-10-04，用户已确认 V01/V02/V03 实施及同一独立测试实例更新。本地验证与独立审查完成；新候选已通过正式上传安装，重新打开正常登录的真实插件页面后，单次 44091 的 bridge、公开业务结果及新样式回归通过。历史与模拟证据仍单独记录。

## 已确认范围

- 沿用现有动态模块页、SDK 1.4、真实 bridge 与正式查询鉴权；保留已通过的物品 44091 页面闭环、候选 ID 重查、输入错误、重复提交、停止展示、窄屏及键盘行为。
- 日历由外部维护。本次活动内容未通过，延期；不阻塞物品和已测页面工作，不要求修复上游或补齐活动。
- 日历失败必须显示不可用及手动重试入口，不能显示成“没有活动”或假成功。HTTP 200 中携带业务 error 是现有响应契约，保持该契约。
- 只做物品/日历查询页的局部视觉和必要文案，不改导航结构、鉴权、数据源、错误码、数据库、身份、市场、Dota2、订阅或整体 UI。不自动查询或重试，不要求停止展示取消后台请求。

## 现有页面与改动建议

现有页面由 `pages/ff14/app.js` 和 `styles.css` 构成；查询表单、本次结果与聊天替代是既有区域。修改前主按钮占整行；当前实现采用限定查询卡片的样式，结果标题、长获取途径、来源和警告均保留。日历错误保留参数摘要和原提交按钮。下表为本批已实现范围，运行态覆盖仍按末节分层判断。

| 优先级/切片 | 建议 | 最小范围 | 验收不变量 |
| --- | --- | --- | --- |
| V01，优先 | 强化错误和部分成功的视觉区分：沿用红/琥珀色，加浅底色及细边线，保留文字；提高标题、正文、来源的层级和段落间距 | `styles.css` 中物品/日历查询结果内的 `.notice.error`、`.notice.warning`、`.result-text`、`.hint`；必要时仅补限定路由的 class/data 属性，不改全站提示 | 来源、缺项、截断提示和全部 warning 保留；错误仍有 alert；不靠颜色独立表达状态 |
| V02，随后 | 桌面查询按钮采用紧凑宽度，与表单左边对齐；移动端继续满宽。控件/卡片间距统一，长材料和来源链接自然换行 | `styles.css` 的物品/日历 `.query-submit` 和查询区域，必要时沿用V01的路由限定属性；保留 719/720 断点 | 不改 DOM 操作顺序，不隐藏焦点，不增加水平溢出，控件最小高度保持 40px |
| V03，必要文案 | 日历 error 状态将同一个现有提交按钮标为“手动重试日历”，加载时恢复禁用。保留当前“来源暂时不可用，请稍后手动重试。”与输入范围说明 | `app.js` 的 `updateQueryUi()` 中日历按钮标签，相关离线断言 | 不新增第二套请求处理器；点击/Enter仍走同一 submitQuery；一次提交一次逻辑请求；不编造主备状态、活动或重试时间 |

不从 `TextBlock` 的中文文案拆取材料、任务或活动重建字段，不删除正文和 warnings 中各自承担的说明，不添加未经验证的日历新鲜度标签。不新增外部字体、图标库或样式依赖。

## 视觉和交互细节

- 继续使用现有蓝色主按钮及浅/深主题变量。错误提示保持清楚、安静，浅底色也需适配深色主题；不以大面积红色覆盖整个结果区。
- 物品名作为结果内容主标题，ID/对象作为辅助信息；任务与材料仍为原始安全文本。来源链接与来源口径保留可见，不折叠缺项提示。
- 日历不可用区域仍显示错误、用户输入的区域/天数/时区和同一表单的手动重试入口；这些参数不冒充来源实际覆盖窗口。没有 document 时不画空活动表。
- “刷新状态”与“手动重试日历”保持不同用途；状态刷新、切页、恢复连接均不自动查外网。停止展示后的旧结果仍不能出现。

## 最小实施与验证

1. 先实施 V01+V02，限定 CSS 与必要 class；独立审查后冻结版本。V03作为第二个可单独审查的小切片，不顺带改错误分类或请求生命周期。
2. 复用离线命令 `node tests/pages/ff14/test_ui_a.mjs`；若涉及结果节点/class或展示文本，再运行 `node tests/pages/ff14/test_item_display.mjs`，明确 `YGL_TEST_PYTHON` 指向已确认版本的隔离解释器，环境准备沿用 CONTRIBUTING。不为了样式复验清理全仓历史失败。
3. 视觉验证浅/深主题、375/719/720/1280 所测尺寸，检查标题、长材料、来源/警告、错误和焦点。离线错误 DTO 可验证错误呈现，单独标为离线，不能称真实上游内容通过。
4. 页面样式变更后的真实实例复验需要匹配候选版本及用户明确更新授权；本方案不授权自动部署。依据资源加载和缓存合同选择最小必要重载，不默认要求实例冷启动。最小真实业务回归为一次 44091；日历内容继续延期，不为截图反复请求外部来源。重复提交/停止展示的回归可先用既有离线用例验证，真实未重测部分保留历史覆盖范围。

本批实施仅上述已确认范围，不要求先恢复外部日历服务、增加 QQ 连接或重构整体页面。没有自动提交、推送或部署。
