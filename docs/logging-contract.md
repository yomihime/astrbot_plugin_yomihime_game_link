# 日志分级与诊断边界

本契约用于 Core、SDK 服务与受信模块后续维护。正常运行不逐条记录成功请求；打开 DEBUG 后，以调用 trace 关联阶段、来源、耗时和有限错误类别。日志级别由宿主控制，不增加插件专用开关。

| 级别 | 适用范围 | 不应放入 |
| --- | --- | --- |
| DEBUG | 有界调用阶段、成功/失败终态、预期取消/生命周期失效、排查用模块事件 | 原始请求/响应、异常字符串、身份、凭据 |
| INFO | 启停、安装/更新完成等低频状态变化 | 每次查询成功、每轮调度无变化、每个缓存命中 |
| WARNING | 当前请求失败，或有明确上游故障证据的部分结果；同调用聚合一次 | 正常无数据、用户输入错误、正常取消、旧生命周期工作结束 |
| ERROR | 后台调度等服务意外停止，已不能继续工作 | 可重试的一次 HTTP 超时、正常禁用/卸载 |

## 已接通的路径

- Core 公共 command/tool/web 调用及公共采集在终态通过 `GAME_LINK_TRACE` 输出一条 DEBUG 摘要，包含经严格语法和长度校验的模块标识、能力或采集器标识，至多 48 个阶段事件和丢弃计数。标识来自已验证声明，不来自查询参数、用户或群身份。默认 DEBUG 未开启时不复制/序列化该摘要。
- 终态 `GAME_LINK_FAILURE` 提供安全类别和 `failure_stage`；有 HTTP 失败时附带最后一条安全 HTTP 元数据。模块已输出 warning 时不再重复。
- `partial_success` 只有同时记录到该调用的真实 HTTP 失败才产生 `partial_upstream_failure`。单纯部分数据、无数据不报警；成功恢复的完整结果仅保留 DEBUG 证据。这表示两者同次发生，不推断所有缺项均由该错误造成。
- 新闻采集的 `FF14NewsFailure` 通过 SDK diagnostics 记录列表/详情阶段、固定类别、HTTP 状态和耗时。FAILED 观察还有 Core 兜底告警；失败不改动公告游标、去重或重发策略。
- 调度 pump 意外停止输出 ERROR；正常取消不报 ERROR。

## 安全与预算

日志不得包含查询参数、角色/用户/群身份、消息正文、HTTP body、完整 URL、Cookie、Authorization、Token、数据库内容、文件系统路径或未筛选的异常/堆栈。只使用受信逻辑来源/阶段、有限错误类别、HTTP 状态、计数、耗时和随机 trace。模块事件先经过闭合 schema 与长度预算。私有调用不进入公共 Core trace/warning。

日志失败不能覆盖业务结果；取消、权限撤回和实际截止仍按控制流处理。事件环、序列化大小与单调用警告预算不能因开启 DEBUG 而解除。

## 覆盖边界

本轮修复覆盖公共调用、HTTP、公共采集及新闻链路，不代表全仓每个历史 catch 都已完成分类。HTTP 200 后由模块自行吞掉的解析错误，通用层无法可靠推断；此类链路需要模块提供安全事件。投递 outbox、发送结果 UNKNOWN、渲染等流程需分别验证其阶段及状态语义，不得以告警或日志重试代替既有防重发规则。部署后的宿主日志等级与真实投递仍需实际验收。
