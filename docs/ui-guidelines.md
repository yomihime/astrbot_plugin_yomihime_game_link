# Yomihime 插件 UI 规范

本规范面向仓库内 Vue / Naive UI 页面；第一版样板为全局设置和 FF14 配置。不新增 UI SDK、宿主授权或业务合同。

## 导航与信息层级

外层宿主导航保持原样。插件侧栏使用完整品牌、首页、当前目录中的模块，底部为全局设置。桌面宽度 258px，999px 以下为 220px，719px 以下使用移动导航。模块默认进入主页；内部配置按实际管理声明显示，辅助查询按模块现有页面 descriptor 显示，无能力不造空业务页。

首页提供模块入口，`#/modules` 单独负责模块生命周期管理；健康未知保持未知。模块根 `#/module/<encoded-owner>` 按 home role 挂载，业务配置使用实际 config role 路由；`#/module/<encoded-owner>/-/queries` 只列 aux 页面。全局设置为 `#/settings`。旧 `#/settings/module/<encoded-owner>` 不再路由到壳内业务表单。浏览器前进、后退及刷新使用同一 hash 路由和离页确认。

## 密度与组件

公共实现位于 `pages/frontend/src/ui/`。`PageHeader`、`SettingsGroup`、`SettingsRow`、`ActionBar`、`StatusHint` 只负责呈现，调用方持有权限、草稿、确认和请求状态。

|项目|约定|
|---|---|
|字号|正文 15px，页面标题 28px，组标题 18px，辅助状态 13px|
|间距|4 / 8 / 12 / 16 / 24 / 32px，组内 16–20px，组间 12–16px|
|控件|文本输入、选择和按钮最小高度 40px，短 210px、中 320px、长最多 560px；checkbox/radio 为固定 20×20px，不参与 flex 收缩|
|标签|桌面约 128px；窄屏放控件上方，不用 placeholder 代替|
|行|标签、适长控件、字段恢复默认，行距 8–12px，无每字段分隔线|
|颜色|`tokens.css` 的 panel / text / muted / border / accent / error / warning / success；与 Naive 浅深主题同步|

正例：三行日历用短数值、时间、中等时区输入；错误紧跟字段；主要保存按钮紧邻本组。反例：短数值全宽、常驻大成功框、靠缩字或缩点击范围压密度、隐藏冲突、把所有业务入口塞进侧栏。

## 状态与交互

初次加载、重入和内部读取成功保持安静；用户主动刷新显示“已刷新”，保存显示“已保存”，3.5 秒后消退，无消息时不保留提示框占位。错误、冲突、未保存和部署警示不自动消失；通知计时器绑定消息代次，挂起、上下文替换、关闭时撤销，旧回调不能清掉新错误。加载和刷新保留表单主体及输入节点；按钮通过既有单飞/current 栅栏拒绝重复写，避免焦点被忙态原生 disabled 意外抢走。键盘标签、可见焦点和正常 Tab 顺序必须保留。复选说明使用 `.ui-check-label` 包裹原生控件与文字，整段可点击，多行从首行对齐，浅深色与窄屏保持尺寸。

普通设置只呈现语义字段、必要说明及问题、保存/放弃操作；不呈现 owner、revision、schema、存储来源等技术明细。首页和模块主页保留生命周期管理，设置页不重复这些卡片。配置维护由明确入口单独挂载，关闭即释放；它复用原受审回退/恢复能力，所有动作仍经过主壳全局草稿与当前性确认，不能借独立实例绕开别处草稿。表单和维护 scope 的 refs/事件均按实际 DOM 绑定，不放隐藏占位控件。

“刷新模块状态”刷新目录及运行代际；“刷新配置与版本”读取配置/凭据状态及当前 CAS 版本，两者不能互相替代。普通设置保存与凭据保存使用不同接口，但同一 owner 共用 revision；每次保存成功刷新两类 snapshot，下一次保存使用新版本。组成功不表示其它组已提交，不并行旧版本、不宣称跨接口原子事务。

写入 ACK 和写后读取分别判断；写入已接受但目标状态未核验时持续提示“已提交，状态暂未核实，请刷新确认”，禁止自动重发或用旧版本继续写。只读有效、无授权、无效配置、未知健康、凭据未配置、加密不可用分别表述，不把 unknown 当错误或成功，不显示裸原因码。

字段“恢复默认”通常只产生该字段的 clear 草稿；有明确禁止 CLEAR 合同的字段可由模块可信呈现声明 `reset: replace-default`，仍通过 schema 和精确授权校验，只形成 REPLACE 声明默认值草稿。FF14 订阅开关使用这一策略，其它布尔字段不自动套用。普通保存保持 owner 范围。“放弃本模块修改”恢复该 owner 的普通草稿，并清空该 owner 的凭据草稿。离页确认按当前 owner 普通草稿与全 owner 将清凭据计算；取消保持，确认保留普通草稿、清空秘密。地区切换使用稳定 keyed 节点和 hidden 保留两区草稿。凭据显隐仅显示本次输入，服务器已存秘密永不读回；清除仍需明确勾选确认。存储成功不代表上游验证成功。

加密不可用时只描述已证状态；不得推测密钥缺失/格式错误或让用户在表单粘贴部署密钥。管理员检查宿主部署；外部启动环境变更需正常重启同一宿主后重开页面，插件重载或刷新不能保证继承新环境。存在已保存凭据时应保留原部署密钥，本页面不生成或轮换密钥。

## 模块呈现扩展

模块自己的页面负责业务标签、字段顺序、控件和凭据地区呈现；壳不再通过 `presentation.json` glob 读取模块装饰，也不渲染旧通用业务配置表单。模块只消费 [公开前端合同](../pages/public-contract.ts) 中受限的 owner 绑定服务，字段描述与主题选项来自被授权的安全 DTO；声明本身不授予权限。接入方式以 [前端模块合同](frontend-module-contract.md) 为准，FF14 的具体业务界面见 [模块说明](../modules/ff14/README.md)。Core 全局设置的通用呈现仍由公共层持有。

## 本地参考与检查

仓库根运行 `npm.cmd run reference --prefix pages/frontend`，打开 `http://127.0.0.1:18762/reference.html`。这是轻量组件页，支持浅深主题和 loading / dirty / error / conflict / readonly / success 状态，无宿主连接和业务请求。

运行 `npm.cmd run typecheck --prefix pages/frontend`、`npm.cmd run build --prefix pages/frontend` 与受影响测试。构建同时更新壳内设置视图和必要发布资源；设置仍通过壳内设置视图进入，不是独立页面入口。视觉验收使用隔离 bridge 回放，记录 CSS 视口、缩放、DPR；比较桌面配置、窄屏和深色，再抽查主页/辅助查询。离线 DOM、真实浏览器、宿主 HTTP、真实上游分别记录，互不代替。

## 单入口职责

正式页面根只有 `00-game-link`。首页、模块管理、全局设置及 Module 页面是该根内的视图；Module 按 home/config/aux 角色进入壳。管理与模块操作仍由各自后端授权合同约束，独立授权不表示另有页面根。接入合同见 [frontend-module-contract.md](frontend-module-contract.md)。保持现有紧凑紫金视觉和共用 SettingsGroup、SettingsRow、ActionBar、StatusHint。正常就绪时收起恢复与全域危险操作，异常时给出简短可执行路径；确认绑定当前 owner、revision 与生命周期。
