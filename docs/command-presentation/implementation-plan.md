## 执行约定

- 每次只处理一个有明确边界的任务卡，完成出口验收后再推进
- 遵守仓库现有开发约定与 [CONTRIBUTING.md](../../CONTRIBUTING.md)，先读相关代码再改
- SDK 维持 `0.1.0a6`；需要改变公共契约时先停下报告，不偷偷扩展接口
- 同一 Draft PR 逐步追加提交；不重置分支、不重命名任务来绕过未决问题
- 每阶段最多两轮针对性修复；仍有失败就交代证据与缺口，避免无边界重写
- 只在授权范围内继续提交与推送，不自动合并、发版、部署或修改真实实例
- 不调用付费模型测试，除非另有明确预算授权

## 每次续作的任务卡

开始前在 PR 进展中填清楚下面五项，避免把整份路线图当作一次无边界任务：

1. 当前阶段与唯一目标，例如“P1 修复已复现的三处间距”
2. 允许修改的文件或子系统，以及本轮不触碰的边界
3. 需要的证据和完成条件，包含具体测试与观察层次
4. 当前阻塞和需确认的决定，特别是凭据、发布状态、舍入与依赖
5. 本轮结果：改动、测试、未运行项、残余风险、下一张任务卡

先报告可用成果和阻塞，再附细节。两轮修复后仍无法通过时交回准确问题，不把测试失败、元数据缺失或未验证的真实投递包装成“已完成”。
