# 模块开发者展示样式 Spec

更新日期：2026-10-16（文档日期，非查询或数据更新时间）

适用：`astrbot_plugin_yomihime_game_link` 的模块开发者。通用富文本已进入 production presentation，Python 参考复用同一内核；生产接线与真实 Host 验收状态以 [当前交付记录](README.md) 为准，离线样图不证明目录类别或真实成绩语义。

## 1. 边界与状态

三层交付必须分开：

- **设计蓝图**：本文规定语义、职责、可读性及发送前降级约束；概念富文本结构不扩展公开 SDK
- **离线参考**：`examples/command_cards/rich_text_reference.py` 薄适配共用的 `presentation/rich_text.py`，`ff14_logs_reference.py` 保留 FF14 分级、格式和合成布局；测试入口为同目录 `test_style_reference.py`。不取得真实数据或业务等级证据
- **生产状态**：通用 PNG 具有内部 `RichText` / `TextCell` 绘图入口及固定字体/授权资源基础，Host 图片链已接线。FFLogs 目录类别、区域开放范围和原始字段含义必须分别取得来源证据，不能以图片成功代替。SDK 保持 `0.1.0a7`，本轮显示修订不改公共契约

本轮测试结果按实际执行记录单独报告，不把参考脚本通过等同全仓通过，也不改写[历史集成失败](README.md#p5-本轮集成结果)。

**本版采用的设计约束**

- Core 提供通用渲染器、主题与富文本样式；Module 负责业务含义、评价映射、内容和布局。薄 SDK 的公开接口改动不作既定假设
- 指令回复可选品牌图片，并始终准备确定性的纯文本。图片渲染失败时，仅在发送提交前切换为文本；提交后失败不得盲目补发，避免重复
- LLM 路径仅输出事实，不生成图片，不随机插入品牌文案
- 暖桃色保留为可选预设，支持其他主题和自定义配色，FFLogs 卡片最终主题尚未选定，深色也未被确认为默认。主题只调整背景与普通文字；等级字面色保持稳定，辅助柔影按下文已选配方随实际背景派生
- 品牌图片页脚固定为 `Powered by yomihime/astrbot_plugin_yomihime_game_link`

**待确认的实现建议**

- 下方富文本结构仅用于说明本地表达方式，不是新增 SDK API
- rDPS 展示整数并使用千位逗号；具体取整采用 half-up 四舍五入，作为实现建议等待确认
- 错误红色暂建议 `#c83e4d`，须核验各主题对比度；此色值不是用户指定的固定要求
- 背景正在比较冷白、雾紫、灰蓝、深靛主题；暖桃色不视为已确认的 FFLogs 最终主题

## 2. 颜色与数值语义

百分位先用**原始值**分级，再以十进制精确处理，使用 `ROUND_DOWN` 保留一位小数，只舍不入，不做中间舍入。`99.99 → 99.9%`、`95.29 → 95.2%`、`43 → 43.0%`、真实 `100 → 100.0%`。严禁按展示值重新分级；工具 facts 保留原始数值，不回写展示字符串。这项决定覆盖此前百分位 `ROUND_HALF_UP` 参考，不改变 rDPS 的整数千分位规则。

| 等级 | 固定色 | 原始百分位 p |
|---|---|---|
| 灰 | `#666666` | 0 ≤ p < 25 |
| 绿 | `#1eff00` | 25 ≤ p < 50 |
| 蓝 | `#0070ff` | 50 ≤ p < 75 |
| 紫 | `#a335ee` | 75 ≤ p < 95 |
| 橙 | `#ff8000` | 95 ≤ p < 99 |
| 粉 | `#e268a8` | 99 ≤ p < 100 |
| 金 | `#e5cc80` | 原始 p = 100，并有相应满分证据 |

- 复用 FFLogs 等级色不等于复用其业务定义。非百分位数字、文字评价，仅在模块有合理、可说明的比较标准及映射时使用等级；不得任意归一化 DPS、价格等数值
- 金色要求在明确的评价范围内，有来源支撑的评价上限或“超过全部比较对象”等证据；不能因本次样本最佳或四舍五入为 100 就授金。FFLogs 的 100 不额外解释为“伤害无法再提高”或“全球第一”
- 红色只表达警告、错误或需要注意的异常，不作高分色
- 错误显示红色 `ERR`；缺失值显示主题文字色 `—`；不可评价值保留原始数据并使用主题文字色；有效 `0` 必须正常展示
- 不能只靠颜色传意：同时展示数值、百分位或等级文字；确保各主题可读
- 已确认的布局：百分位列右对齐、垂直居中；各等级背景一致，绿/金色不另加深色底板；特效围绕字形，不另做徽章

### 已确认的字效方案

- 所有等级使用上表精确字面色，浅色与深色主题一致，金色始终为 `#e5cc80`，不替换为琥珀色
- 可读性层采用 **B「居中柔影」**：适用于全部文字角色，只在字面色与实际背景的对比度 `< 1.5` 时启用。使用原始字形蒙版、零偏移的高斯模糊；原型参考为 35 px 字号时约 1 px 模糊，不膨胀蒙版、不做硬描边
- B 柔影色沿用已选原型配方：将实际背景逐 RGB 通道反色，再与字面色取中点，透明度参考 235/255；仍为零偏移、零描边的模糊原始蒙版。B 替代的是此前扩张描边几何，颜色配方继续保留。先合成辅助层，最后绘制精确颜色的清晰字面；对比图中强制启用的深色主题灰字仅是测试，不是生产触发规则
- 装饰层 **A「贴字柔光」**独立保留，仅用于证据成立的真实金色满分（MAX），可轻微扩展；不得套用于其他等级。A 与条件启用的 B 均先于清晰字面合成，不要求动画

### 当前参考的复现参数

以下是离线实现的明确选择，不扩展 SDK，也不是生产资源预算的替代：

- 栅格倍率 `SCALE=2`，令 `k=字号/35`；每边留白 `ceil(27*k*SCALE)`。B 的高斯半径为 `1*k*SCALE`，模糊后 alpha 为 `round(mask*235/255)`；中点 RGB 按 Python ties-to-even 取整，无蒙版膨胀、偏移或描边
- A 从原字形蒙版生成三层 `(半径, power)`：`(1.2,0.85)`、`(3.8,0.98)`、`(7.2,0.46)`；半径乘 `k*SCALE`。实际背景相对亮度 `< 0.179` 时，取 `alpha=min(255,round(mask*power))`，将 RGB `(238,186,61)` 各通道乘 `alpha/255` 后逐层 screen，累计相对原图的增亮逐通道限制为 `(160,125,65)`；其余背景按 `alpha=min(155,round(mask*power*0.75))` 依次合成 `#ebc361`
- A 装饰颜色不改变金色字面 `#e5cc80`。整行先采样真实底色并合成全部效果，再绘制全部清晰字面，避免后一个 span 的辉光覆染前一个 span
- 每 span 最多 512 字、每行最多 1024 字 / 32 span，字号 8–96；单字效 patch 每边不超过 4096、实际 2 倍栅格像素不超过 1,000,000，整行保护蒙版不超过 2,000,000 像素。沿用既有 Canvas 上限，超限明确报错，不静默裁剪

## 3. FFLogs 模块示例

一张长卡包含“绝境战”和目标资料片“零式”。目标资料片先采用所选 FFLogs source 默认 zone 所属资料片，使用其来源名称；这是来源目录范围，不声称独立证明了该地区游戏当前完整开放状态。只有该资料片目录没有符合下述条件的零式时，才按已核验的上游资料片顺序回退；角色空统计、未打过或查询失败不是回退依据。不添加汇总记录数标签。此约定覆盖此前以独立地区开放证明作为展示前置的方案。

标题、区域、版本、Boss 等元数据自动获取；不维护缩写硬编码表。优先采用已核实来源的本地化名称，无可靠翻译时保留原名。标明查询来源及实际数据日期；不能把文档日期、抓取时间当作战斗日期。

零式同时满足目标资料片、目录声明的零式难度及八人范围，查询响应的 selection 再核对难度和人数；各区 difficulty ID 从目录解析，不把某个 ID 当通用常量。四人、四十八人及其他范围排除，普通难度全部舍弃，零式无记录不能用普通成绩补位。零式按实际来源 zone/tier 分区，保留来源 encounter 顺序；门神与本体不同 ID 不合并。只有被选入目录并成功查询但无成绩的项才显示缺失 `—`；未查询、请求失败和成功无成绩分别保留状态，错误不补零，不暗示角色未通关。

目录人数未知不等于没有零式：仍可将该零式难度作为待核候选，只有实际 selection 证实八人及对应难度后才展示成绩；不能填造人数，也不能据此触发上一资料片回退。实际 selection 返回普通或四人、四十八人时，排除该非目标分区，不将其伪装成零式空行或错误行。

绝境候选允许采用 zone **或 encounter** 完整来源名含“绝境”/`Ultimate` 的命名约定，同时验证 encounter 的规范 zone 归属。这是明确、可测试的命名规则，不宣称 API 有内容类别字段；英文 zone 不能使中文 encounter 漏选。只对 Unicode、空白等作有限规范化，以完整来源名称建立展示组，内部保留所有独立 zone/encounter 标识；不作简称、模糊相似度或 LLM 合并，不能可靠关联时保持区分。绝境使用目录实际难度，不因该难度名为“普通”而被零式规则排除。

每个绝境展示组最终一行：查询可识别的历史范围，用未截断的原始百分位选择最高的整份结果；同分且有可靠时期顺序时优先较新时期，否则采用稳定、可复现的标识次序。职业、rDPS 和次数均保留所选结果范围，不跨时期拼接或累加。标注所选来源资料片或分区时期；只有可靠字段证明 patch 才写 patch，不将 partition ID 当游戏版本。含义是“已查询范围内的历史最佳百分位”；任一历史范围失败或未查，明确不完整，不声称完整历史最佳。样本中的名称数量和独立 ID 数不是生产上限。

查询分批、并发有界并共享总期限；查询与展示触及上限时都明确部分范围，不静默挤掉整个类别。两类别仍保留可用结果和简短失败/未查询提示。Core 只渲染模块提交的内容，不判断游戏类别或历史优劣。

有界调度先覆盖不同展示组与零式分区，再覆盖各独立 zone/difficulty 历史来源，最后按来源轮转更多 partition，避免同一新来源的大量时期挤掉旧来源。每个来源先选目录明确的默认时期；没有默认标记时按来源目录首项，不猜时期先后。共享目标去重，图片仍保留来源目录顺序；达到上限继续明确未查范围。

以上独立来源优先仍是待完成目标：当前交付 R1 只保证展示组与类别优先及明确部分范围；R2 候选因混合类别共享来源的目标覆盖缺陷未通过最后独审。来源被选中不等于该桶的完整三元组目标已被覆盖，显式 partition 与默认 `None` 必须分辨。当前状态见[交接入口](README.md)，不能将本段目标冒充已交付保证。

记录版本仅在有可靠字段或关联时紧凑展示；没有证据时省略，不逐行输出“记录版本 —”，不把 FFLogs partition 编号或当前版本当成历史战斗版本。最高 rDPS 与最佳百分位可能来自不同记录，图片保留简洁提示，不把职业、次数和两项最佳合并声称为同一场成绩。

### 职业身份与语言

职业本地化属于 FF14 模块。来源职业值与稳定模块身份、显示名分开：`fflogs_jobs.py` 解析明确已知的 FFLogs 名称/缩写，图片默认中文全名；facts 的来源值保持不变。Core/SDK 不持有 FF14 职业表。不做模糊匹配或 LLM 翻译；未知职业保留原文并完整换行，不截断或猜一个相近职业。

| 语言 | 显示规则 | 示例 |
|---|---|---|
| 中文 `zh`（本轮默认） | 官方简体中文全名 | 学者、占星术士、贤者 |
| 日文 `ja`（结构预留） | 官方日文全名 | 学者、占星術師、賢者 |
| 英文 `en`（结构预留） | 标准职业缩写 | SCH、AST、SGE |

这不是全插件三语言切换工程。28px 字号下日文 `ガンブレイカー` / `ピクトマンサー` 各 7 字，职业列采用语言相关权重，在 1040px 卡片内约 234px（内容约 210px，含 24px 内边距），容纳约 196px 字形。保持整图宽度，数字列继续右对齐、百分位字形垂直居中；未知更长职业完整换行。中文和英文保留紧凑列宽。

每个 Boss 展示 `totalKills`，要求非负整数，使用普通文字色。其含义是 FFLogs 记录到的击杀数，不是角色终身全部击杀，也不是 `len(ranks)`。现有客户端可按 encounter ID 对应 `zoneRankings` 条目，但具体字段必须检查客户端及真实本地 fixture；不把未核实 JSON 形状宣称为官方接口契约。

- 图片底部的数据来源简写为 `数据源：cn.fflogs.com` 或 `数据源：www.fflogs.com`，只使用实际查询地区对应的一个域名，不同时列出两者；用来源行替代击杀数口径长脚注，统计含义保留在本 Spec 中
- 正式图片不放冗长的样式图例、调试文字或示例说明；演示角色 `ChatGPT@OpenAI` 及其数据仅为样例，不代表实际 FFLogs 查询结果

## 4. 参考接口与概念结构

`rich_text_reference.py` 复用共用内核并保留示例接口：`TextSpan(text, role, grade)` 只接收受限文字和语义角色；`draw_rich_line` 绘制同一基线的多个 span，`draw_metric` 按实际字形边界右对齐、垂直居中。B 对全部文字角色按真实底色和 `< 1.5` 条件触发，包括普通、次要、缺失及不可评价文字；背景从已有画布采样，不接受调用方自报背景来绕过条件。普通、缺失及不可评价值仍保留其主题字面色，不新增特殊等级或样式。

`ff14_logs_reference.py` 的 `percentile`、`rdps`、`count` 将模块值转换为 span；`Unevaluable` 明确区分不可评价原文与无效数值，`None` 表示缺失。`percentile(100)` 的前置条件是模块已验证 FFLogs 来源、范围及满分含义；该 helper 自身不取得证据。可运行示例及 CLI 见 [参考说明](../../examples/command_cards/README.md#最新模块富文本与-logs-样式参考)。

共用内核提供有界字效会话，完整 `CardSpec` 的富文本换行和单元格对齐由 `card_bitmap.py` 内部新增类型负责；参考 Canvas 的多次调用共享累计计量。下方 YAML 仍是概念蓝图，不是这些 Python 类型或公开 SDK 的可执行输入。最终验证状态和工作位图/字体模型见[当前检查点](README.md#续作-b共用富文本内核2026-10-16)。

以下是概念性本地结构；示例数值不代表任何真实角色，品牌资源仅使用预置白名单资源。

```yaml
card:
  theme: warm_peach # 可选预设示意，非最终 FFLogs 主题
  palette: { background: "#fff4ee", text: "#4b3b35" }
  paragraphs:
    - spans: [{ text: "Boss 名称（来源元数据）", style: title }]
  rows:
    - spans:
        - { text: "百分位 " }
        - { text: "99.9%", grade: pink } # 原始 99.96，只舍不入
    - spans: [{ text: "击杀数 0" }]      # 有效零值，普通色
    - spans: [{ text: "缺失项 —" }]
  footer: "Powered by yomihime/astrbot_plugin_yomihime_game_link"
```

模块提交文本、受限样式与等级语义；Core 复用安全的字体、尺寸、换行及资源预算。不接受任意 HTML、SVG、运行时资源路径或网络资源；长文本和不可信内容不得突破渲染限制。不得静默裁剪事实；超限时在发送提交前改用完整文本回退，仍无法完整发送则请用户缩小范围。文本回退由同一事实数据确定性生成。

## 5. 实施前验收清单

- 分级边界：24.999→灰、25→绿；49.999→绿、50→蓝；74.999→蓝、75→紫；94.999→紫、95→橙；98.999→橙、99→粉
- `99.95`、`99.99`、`99.999` 均展示 `99.9%`，仍为粉；原始 100 且证据成立才显示金色 `100.0%`。补测各分界前后、字符串和 Decimal、空值及非法值。越界、无效及证据不足的数据不得被强制变成满分
- 分别验证缺字段、null、错误、有效 0、不可评价数据；仅错误显示红色 ERR
- 浅/深主题字面色逐项保持一致；所有文字角色仅实际对比度低于 1.5 启用 B，等于或高于 1.5 不启用。核验零偏移、不膨胀、无硬描边、整行字面最后合成及邻接 span 不被覆染，以及 A 只用于真实金色满分；不把强制灰字测试带入生产规则
- 核验真实本地 fixture 的 encounter 对应关系、`totalKills` 字段和统计口径；缺失字段不得猜数或按排名条数替代
- 默认 source 资料片有合格零式目录但角色空统计时不回退；目录确无合格零式才按已核来源资料片顺序回退。分别核验绝境命名/归属/历史完整名称分组与原始最佳选择、八人零式/普通隔离、未查询/失败/无记录；不以独立地区开放证明缺失停止展示真实已返回成绩。无可靠本地化时展示原名，无汇总记录数标签
- 验证图片成功、提交前渲染失败、提交后发送异常、长文本及替代主题；LLM 路径无图片或随机品牌输出
- 同一长图保留绝境战/零式大类和真实 tier 名称；中文职业不透传已知英文全名，日文 7 字名与未知长名不遮挡数字列，不出现无条件版本空标签。固定 Noto 字体分别检查浅/深主题、相邻字效、合成 20 行及未知长名；保留历史确认样图，新渲染另存

当前生产链已采用 SDK a7 声明式卡片和正式图片发送；主题由 Core 预设与模块继承/覆盖控制，默认暖桃纸。参考实现仅是离线复现入口，不提供真实目录或成绩证据。真实 FFLogs 分类、地区开放范围、记录字段及本轮安装后的分层验收仍须按[当前交接](README.md)核对；rDPS 沿用现有整数规则，本轮只改变百分位的小数显示。
