# 模块开发者展示样式 Spec

更新日期：2026-10-15（文档日期，非查询或数据更新时间）

适用：`astrbot_plugin_yomihime_game_link` 的模块开发者。本轮是展示蓝图与独立 Python 参考实现，不是生产图片接入。

## 1. 边界与状态

三层交付必须分开：

- **设计蓝图**：本文规定语义、职责、可读性及发送前降级约束；概念富文本结构不扩展公开 SDK
- **离线参考**：`examples/command_cards/rich_text_reference.py` 和 `ff14_logs_reference.py` 示范样式与 FF14 模块映射，测试入口为同目录 `test_style_reference.py`；仅处理合成或调用方提供的数据
- **生产状态**：已有通用 PNG、内部授权资源与固定字体基础，Host 图片读取、发送和 FFLogs 新目录聚合仍未接通；真实目录及 `totalKills` 字段仍待受管来源和本地真实 fixture 核验。SDK 保持 `0.1.0a6`

本轮测试结果按实际执行记录单独报告，不把参考脚本通过等同全仓通过，也不改写[历史集成失败](README.md#p5-本轮集成结果)。

**本版采用的设计约束**

- Core 提供通用渲染器、主题与富文本样式；Module 负责业务含义、评价映射、内容和布局。薄 SDK 的公开接口改动不作既定假设
- 指令回复可选品牌图片，并始终准备确定性的纯文本。图片渲染失败时，仅在发送提交前切换为文本；提交后失败不得盲目补发，避免重复
- LLM 路径仅输出事实，不生成图片，不随机插入品牌文案
- 暖桃色保留为可选预设，支持其他主题和自定义配色，FFLogs 卡片最终主题尚未选定，深色也未被确认为默认。主题只调整背景与普通文字；等级字面色保持稳定，辅助柔影按下文已选配方随实际背景派生
- 品牌图片页脚固定为 `Powered by yomihime/astrbot_plugin_yomihime_game_link`

**待确认的实现建议**

- 下方富文本结构仅用于说明本地表达方式，不是新增 SDK API
- rDPS 展示整数并使用千位逗号；具体取整采用 half-up 四舍五入，作为实现建议等待确认
- 错误红色暂建议 `#c83e4d`，须核验各主题对比度；此色值不是用户指定的固定要求
- 背景正在比较冷白、雾紫、灰蓝、深靛主题；暖桃色不视为已确认的 FFLogs 最终主题

## 2. 颜色与数值语义

百分位先用**原始值**分级，再以一位小数展示，严禁按舍入后的值重新分级。

| 等级 | 固定色 | 原始百分位 p |
|---|---|---|
| 灰 | `#666666` | 0 ≤ p < 25 |
| 绿 | `#1eff00` | 25 ≤ p < 50 |
| 蓝 | `#0070ff` | 50 ≤ p < 75 |
| 紫 | `#a335ee` | 75 ≤ p < 95 |
| 橙 | `#ff8000` | 95 ≤ p < 99 |
| 粉 | `#e268a8` | 99 ≤ p < 100 |
| 金 | `#e5cc80` | 原始 p = 100，并有相应满分证据 |

- 复用 FFLogs 等级色不等于复用其业务定义。非百分位数字、文字评价，仅在模块有合理、可说明的比较标准及映射时使用等级；不得任意归一化 DPS、价格等数值
- 金色要求在明确的评价范围内，有来源支撑的评价上限或“超过全部比较对象”等证据；不能因本次样本最佳或四舍五入为 100 就授金。FFLogs 的 100 不额外解释为“伤害无法再提高”或“全球第一”
- 红色只表达警告、错误或需要注意的异常，不作高分色
- 错误显示红色 `ERR`；缺失值显示主题文字色 `—`；不可评价值保留原始数据并使用主题文字色；有效 `0` 必须正常展示
- 不能只靠颜色传意：同时展示数值、百分位或等级文字；确保各主题可读
- 已确认的布局：百分位列右对齐、垂直居中；各等级背景一致，绿/金色不另加深色底板；特效围绕字形，不另做徽章

### 已确认的字效方案

- 所有等级使用上表精确字面色，浅色与深色主题一致，金色始终为 `#e5cc80`，不替换为琥珀色
- 可读性层采用 **B「居中柔影」**：适用于全部文字角色，只在字面色与实际背景的对比度 `< 1.5` 时启用。使用原始字形蒙版、零偏移的高斯模糊；原型参考为 35 px 字号时约 1 px 模糊，不膨胀蒙版、不做硬描边
- B 柔影色沿用已选原型配方：将实际背景逐 RGB 通道反色，再与字面色取中点，透明度参考 235/255；仍为零偏移、零描边的模糊原始蒙版。B 替代的是此前扩张描边几何，颜色配方继续保留。先合成辅助层，最后绘制精确颜色的清晰字面；对比图中强制启用的深色主题灰字仅是测试，不是生产触发规则
- 装饰层 **A「贴字柔光」**独立保留，仅用于证据成立的真实金色满分（MAX），可轻微扩展；不得套用于其他等级。A 与条件启用的 B 均先于清晰字面合成，不要求动画

### 当前参考的复现参数

以下是离线实现的明确选择，不扩展 SDK，也不是生产资源预算的替代：

- 栅格倍率 `SCALE=2`，令 `k=字号/35`；每边留白 `ceil(27*k*SCALE)`。B 的高斯半径为 `1*k*SCALE`，模糊后 alpha 为 `round(mask*235/255)`；中点 RGB 按 Python ties-to-even 取整，无蒙版膨胀、偏移或描边
- A 从原字形蒙版生成三层 `(半径, power)`：`(1.2,0.85)`、`(3.8,0.98)`、`(7.2,0.46)`；半径乘 `k*SCALE`。实际背景相对亮度 `< 0.179` 时，取 `alpha=min(255,round(mask*power))`，将 RGB `(238,186,61)` 各通道乘 `alpha/255` 后逐层 screen，累计相对原图的增亮逐通道限制为 `(160,125,65)`；其余背景按 `alpha=min(155,round(mask*power*0.75))` 依次合成 `#ebc361`
- A 装饰颜色不改变金色字面 `#e5cc80`。整行先采样真实底色并合成全部效果，再绘制全部清晰字面，避免后一个 span 的辉光覆染前一个 span
- 每 span 最多 512 字、每行最多 1024 字 / 32 span，字号 8–96；单字效 patch 每边不超过 4096、实际 2 倍栅格像素不超过 1,000,000，整行保护蒙版不超过 2,000,000 像素。沿用既有 Canvas 上限，超限明确报错，不静默裁剪

## 3. FFLogs 模块示例

一张长卡同时展示全部已开放绝境战与当前资料片全部已开放零式。仅当查询地区的当前资料片尚未开放任何零式时，回退到上一资料片的零式；不按上一期或上一层回退。空统计、未打过或查询失败均不是回退依据。不添加“共 13 条记录”等汇总记录数标签。

标题、区域、版本、Boss 等元数据自动获取；不维护缩写硬编码表。优先采用已核实来源的本地化名称，无可靠翻译时保留原名。标明查询来源及实际数据日期；不能把文档日期、抓取时间当作战斗日期。

每个 Boss 展示 `totalKills`，要求非负整数，使用普通文字色。其含义是 FFLogs 记录到的击杀数，不是角色终身全部击杀，也不是 `len(ranks)`。现有客户端可按 encounter ID 对应 `zoneRankings` 条目，但具体字段必须检查客户端及真实本地 fixture；不把未核实 JSON 形状宣称为官方接口契约。

- 图片底部的数据来源简写为 `数据源：cn.fflogs.com` 或 `数据源：www.fflogs.com`，只使用实际查询地区对应的一个域名，不同时列出两者；用来源行替代击杀数口径长脚注，统计含义保留在本 Spec 中
- 正式图片不放冗长的样式图例、调试文字或示例说明；演示角色 `ChatGPT@OpenAI` 及其数据仅为样例，不代表实际 FFLogs 查询结果

## 4. 参考接口与概念结构

本轮离线接口定义在 `rich_text_reference.py`：`TextSpan(text, role, grade)` 只接收受限文字和语义角色；`draw_rich_line` 绘制同一基线的多个 span，`draw_metric` 按实际字形边界右对齐、垂直居中。B 对全部文字角色按真实底色和 `< 1.5` 条件触发，包括普通、次要、缺失及不可评价文字；背景从已有画布采样，不接受调用方自报背景来绕过条件。普通、缺失及不可评价值仍保留其主题字面色，不新增特殊等级或样式。

`ff14_logs_reference.py` 的 `percentile`、`rdps`、`count` 将模块值转换为 span；`Unevaluable` 明确区分不可评价原文与无效数值，`None` 表示缺失。`percentile(100)` 的前置条件是模块已验证 FFLogs 来源、范围及满分含义；该 helper 自身不取得证据。可运行示例及 CLI 见 [参考说明](../../examples/command_cards/README.md#最新模块富文本与-logs-样式参考)。

当前 helper 是有界单行参考，调用方负责换行或发送前降级；下方完整 card / paragraph / row 仅为蓝图，不暗示这些类型已在 SDK 或生产渲染器实现。

以下是概念性本地结构；示例数值不代表任何真实角色，品牌资源仅使用预置白名单资源。

```yaml
card:
  theme: warm_peach # 可选预设示意，非最终 FFLogs 主题
  palette: { background: "#fff4ee", text: "#4b3b35" }
  paragraphs:
    - spans: [{ text: "Boss 名称（来源元数据）", style: title }]
  rows:
    - spans:
        - { text: "百分位 " }
        - { text: "100.0", grade: pink } # 模块根据原始 99.96 判定
    - spans: [{ text: "击杀数 0" }]      # 有效零值，普通色
    - spans: [{ text: "缺失项 —" }]
  footer: "Powered by yomihime/astrbot_plugin_yomihime_game_link"
```

模块提交文本、受限样式与等级语义；Core 复用安全的字体、尺寸、换行及资源预算。不接受任意 HTML、SVG、运行时资源路径或网络资源；长文本和不可信内容不得突破渲染限制。不得静默裁剪事实；超限时在发送提交前改用完整文本回退，仍无法完整发送则请用户缩小范围。文本回退由同一事实数据确定性生成。

## 5. 实施前验收清单

- 分级边界：24.999→灰、25→绿；49.999→绿、50→蓝；74.999→蓝、75→紫；94.999→紫、95→橙；98.999→橙、99→粉
- 99.96 展示为 100.0，仍为粉，显示取整不提升原始排名或等级；原始 100 且证据成立才为金。越界、无效及证据不足的数据不得被强制变成满分
- 分别验证缺字段、null、错误、有效 0、不可评价数据；仅错误显示红色 ERR
- 浅/深主题字面色逐项保持一致；所有文字角色仅实际对比度低于 1.5 启用 B，等于或高于 1.5 不启用。核验零偏移、不膨胀、无硬描边、整行字面最后合成及邻接 span 不被覆染，以及 A 只用于真实金色满分；不把强制灰字测试带入生产规则
- 核验真实本地 fixture 的 encounter 对应关系、`totalKills` 字段和统计口径；缺失字段不得猜数或按排名条数替代
- 当前资料片已有零式开放但空统计时不回退；查询地区当前资料片尚未开放任何零式时，才回退上一资料片。核验覆盖全部已开放绝境战及目标资料片全部已开放零式，且无汇总记录数标签。无可靠本地化时展示原名
- 验证图片成功、提交前渲染失败、提交后发送异常、长文本及替代主题；LLM 路径无图片或随机品牌输出

尚待补齐：主题选择、本地客户端/fixture 核验结果、生产接线方案、rDPS 取整确认及分层验收。字效选型已确认；参考实现不代表生产 API 已实施。
