# FF14 模块架构与范围

> 本文描述边界和当前目录，不派发任务。后续范围、测试和配置/UI 统一见 [新计划](../next-stage-plan.md)。本轮仅规划，W1 原卡作为历史保留。

## 当前实现与本期范围

当前实现位于 `modules/ff14/`，通过 `yomihime.manifest.json` 与工厂装入 Core；`module.py` 装配能力、命令、来源和日历采集/评估。公开类型仅从 `yomihime_sdk.api` 导入。

| 职责 | 当前路径 |
| --- | --- |
| 模块工厂/装配与清单 | `modules/ff14/module.py`、`yomihime.manifest.json` |
| 物品查询与来源映射 | `features/items.py`、`features/item_sources.py` |
| 公开角色 Logs、目录/模型 | `features/fflogs.py`、`fflogs_catalog.py`、`fflogs_models.py` |
| 日历来源/ICS/模型/评估 | `features/calendar.py`、`calendar_ics.py`、`calendar_models.py`、`calendar_evaluator.py` |
| 本人订阅命令 | `features/calendar_subscriptions.py` |
| 宿主装配及内置模块信任安装 | `adapters/astrbot/runtime.py`、`adapters/astrbot/bundled.py` |
| 宿主命令、消息出口 | `adapters/astrbot/command_bridge.py`、`adapters/astrbot/message_port.py` |

本期必验国服公开角色 Logs、物品、活动日历与本人订阅；国际服可选。统计网页 output 暂不作为产品验收范围，已有相关代码不因写计划而删除或启用。角色 GraphQL 排名百分位与统计网页人口分位不同，不得混用。

账号绑定、私人报告、市场、招募、石之家与其它游戏保留后续范围。本轮配置表单、Plugin Pages 均为设计，仓库尚无实际页面/schema 产品实现。

## 不变边界

- FF14 处理来源数据和领域含义，Core 负责受控 HTTP、SecretStore 引用、权限、存储、生命周期、调度、呈现和消息发送。
- 模块不能直接调用网络库、SQL、AstrBot、秘密文件或消息发送；宿主集成不能重建第二套 Runtime/Registry。
- 普通设置、Core 配置、模块 enable 状态和秘密引用各自只有一个权威存储。页面只调用经授权的宿主适配端点，不直接读取内部存储。
- 本人订阅管理由可信私聊 actor/conversation 决定 owner/recipient，修改要有 expected_revision。Dashboard 登录用户不自动等于聊天 owner。
- 部分来源失败只降级相应能力。无法安装受信内置模块必须有可操作诊断，不能仅显示“插件已激活/无模块”。

## 来源、展示与状态

物品中文主源是 XIVAPI-compatible；Garland Tools CN 补充获取途径。ID 44091 是用户提供的可复现样例，中文名以执行时规范来源核对。日历主备与物品来源无关，需分别核验新鲜度、窗口完整性和回退状态。

公开角色样例为“如月怜 @ 潮风亭”。显示来源真实提供的职业、副本、rDPS、排名口径、查询/数据时间；无公开记录不自动判断角色不存在或私密。

聊天输出仍通过 DisplayDocument 与 Core renderer；Plugin Page 使用 AstrBot 受限 iframe/bridge，是不同展示通道。图片只作增强，不因图标失败丢失文本。详细配置字段、UI 工作流、错误和用例见新计划。
