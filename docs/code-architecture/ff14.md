## 1. 归属与范围

独占目录为 `modules/ff14/`，维护本模块清单和验证材料。`/ygl ff14` 为建议路由，最终名称由基本设计统一确认；模块 ID 与用户路由分别保存。

核心为角色绑定及公开 FFLogs 查询。物品、市场、招募和活动日历保持可选，不纳入核心依赖。国服/国际服最终支持范围及默认区域仍需统一需求中的待确认项。

本模块不改主体 API、通用渲染器、数据库表、根包清单和其他模块目录。

## 2. 代码职责

```text
modules/ff14/
  manifest.json        局部静态声明
  module.py            工厂、处理器和生命周期
  models.py            角色、查询条件、成绩和指标口径
  identity.py          名称、服务器、区域规范化
  capabilities.py      角色查询及账号操作
  adapters/
    fflogs.py          公开战绩适配
    catalog.py         静态职业/图标来源适配
  display.py           通用展示文档与事实投影
  subscriptions.py     仅在接入日历等可选订阅时存在
```

## 3. 能力契约

内部能力 ID 为建议，不冻结用户操作名。

| 能力 ID | 输入 | 输出 | 入口策略 |
| --- | --- | --- | --- |
| character.overview | 显式角色或当前默认角色、区域 | 公开概览 | 允许自然语言，只读 |
| character.records | 角色、分区、副本、难度、职业、指标 | 对应成绩及百分位 | 允许自然语言，只读 |
| account.bind | 角色名、服务器、区域或候选 ID | 默认绑定 | 必须命令 |
| account.binding | 当前用户 | 绑定信息 | 必须命令 |
| account.unbind | 当前用户及明确目标 | 解绑结果 | 必须命令 |

FFLogs 凭据是模块数据源配置，通过主体受控 HTTP/凭据引用访问，不是用户角色所有权证明。静态素材来源不可用时只降级图标等增强展示。

## 4. 数据模型与口径

| 模型 | 主要字段 |
| --- | --- |
| CharacterRef | 名称、服务器、区域、可选来源稳定 ID |
| RecordQuery | 分区、版本、难度、职业、指标、聚合和百分位口径 |
| CharacterOverview | 角色说明、可用分区和概览事实 |
| EncounterRecord | 副本、职业、成绩、百分位、查询口径和时间 |
| MetricDefinition | 指标 ID、名称、单位、适用范围 |

角色名不作为全局唯一键；更名与服务器变化不能静默映射到他人。保存来源稳定 ID 时仍保留区域和来源范围。

GraphQL 字段在适配器内转换，不传入主体和展示层。来源不支持某指标/分区组合时返回不支持，不自动换成另一指标。百分位默认口径未定前保持显式条件，不把不同口径数值混合比较。

无记录不推断角色不存在或报告私密。只有明确来源证据才返回这些错误，否则使用“未查询到公开记录/无法确认原因”。

## 5. 存储、缓存与展示

绑定关系使用主体服务。模块集合建议为 `server_catalog`、`job_catalog` 和按需保存的 `record_snapshots`，声明各自版本及保留类别。

缓存键包含角色稳定标识或完整名称组合、区域、来源、分区、难度、职业、指标和聚合口径。静态目录与战绩分别缓存，不因目录更新无条件重取全部战绩。

概览使用 fields/metrics，成绩使用 table，辅助图标使用 asset_id。模块负责计算和标注统计含义；主体负责文本、图片及分页。若关键字段缺失仍可返回部分成功及警告。

## 6. 可选能力与并行边界

市场、物品、招募和活动分别声明独立能力和来源依赖，不将其故障汇总为 FFLogs 查询不可用。若接入活动订阅，注册按来源、游戏区域和日历范围共享的采集器；订阅时区与提醒条件在采集后处理。

模块可在没有其他游戏模块时运行，不依赖 Steam。使用主体契约替身验证请求转换和 DisplayDocument，不自行建立 HTTP 全局客户端、数据库或消息发送实现。

未定项：国服/国际服范围、默认服务器/区域策略、分区及统计默认值、指标可用范围、可选功能、静态来源许可。公共契约由主体文档维护，本模块不复制协议定义。
