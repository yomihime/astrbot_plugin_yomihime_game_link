# Steam · 平台模块代码架构设计

> 状态：设计草案，不代表已实现。本文限定模块代码与对接边界，不包含开发步骤。
> 依据：[需求 §6](../requirements.md#6-steam-平台)、[基本设计](../basic-design.md)、[主体公共契约](core.md)、[架构索引](../code-architecture.md)。

> AI 协作入口：[统筹协议](orchestration.md)、[工作包目录](work-packages.md)、[任务卡模板](task-template.md)。实现者只执行已填写任务卡中的范围；本文全篇不是一次性开发任务。

## 1. 归属与范围

独占目录为 `modules/steam/`，维护模块清单和验证材料。`/ygl steam` 为建议路由；公开资料绑定、商品识别和价格是主体能力。历史价格、比较及愿望单的首版范围仍按需求待确认项处理。

本模块同时提供供 Dota 2 可选复用的公开身份解析能力，但不读取或修改 Dota 绑定。禁止修改公共 API、数据库表、根包清单、通用渲染器和其他模块目录。

## 2. 代码职责

```text
modules/steam/
  manifest.json         局部静态声明
  module.py             工厂、处理器及生命周期
  models.py             个人身份、商品、报价、历史价、观察数据
  identity.py           SteamID/资料链接解析
  products.py           商品规范化、候选及版本区分
  capabilities.py       公开查询及账号操作
  adapters/
    profiles.py         公开个人资料来源
    catalog.py          商品目录及检索来源
    prices.py           当前价来源
    history.py          历史价来源
  display.py            通用展示及模型事实
  subscriptions.py      价格采集、事件与筛选匹配
```

具体外部接口需验证，本文只冻结适配职责，不把商店页面或候选 API 当作已稳定接入。

## 3. 注册能力与跨模块接口

| 建议能力 ID | 输入及输出 | 策略 |
| --- | --- | --- |
| identity.resolve_public | SteamID64/资料链接 → 稳定公开身份 | 只读；可供声明依赖的模块调用 |
| profile.public | 显式账号或默认对象 → 公开资料 | 允许自然语言 |
| product.search | 游戏名/ID/商店链接 → 明确商品或候选 | 允许自然语言 |
| price.query | 商品、地区、历史需求 → 当前价及可用历史摘要 | 允许自然语言 |
| price.compare | 多个明确商品及同口径条件 → 比较结果 | 可选，只读 |
| account.bind/binding/unbind | 当前用户的绑定管理 | 必须命令 |
| subscription.* | 订阅创建、查看、修订和取消 | 必须命令，调用主体订阅服务 |

内部身份响应表达 SteamID64、可选有效的 Dota account ID、规范资料链接和来源；具体公共身份响应结构由主体契约维护，不要求 Dota 导入 Steam 模型。

`identity.resolve_public` 不暴露查看绑定、凭据或授权状态。Dota 获取默认 Steam 派生身份仍通过主体 IdentityResolver；显式资料链接解析才通过声明依赖调用本能力。

当前价格、历史价格、资料和目录分别声明可用状态。历史来源不可用可返回部分成功；不能把无法查询史低包装成“不是史低”。

## 4. 业务模型

| 模型 | 关键语义 |
| --- | --- |
| SteamIdentity | SteamID64、资料链接及公开显示字段 |
| ProductRef | 商品类型、ID、名称、版本、商店及地区范围 |
| Offer | 商品、地区、原生币种、原价、当前价、折扣、可购状态、促销截止时间 |
| HistoricalLow | 商店/地区/时间覆盖、最低价、发生时间与来源 |
| PriceComparison | 相同口径的比较项及不可比原因 |
| PriceObservation | 成功对象、失败对象、数据完整性和采集时间 |

商品类型明确区分 app、package、bundle 等支持的范围，未支持类型明确拒绝。金额使用精确数值表示；币种不能唯一推导国家，换算展示不替代原生报价。

永久免费、免费周末、限时领取、未发售、无价格和地区不可购分别表示。个性化捆绑包没有所需授权时只展示公开口径，不声称是用户结算价。

## 5. 存储与展示

账号绑定使用主体关系表；建议集合为 `product_aliases`、`product_catalog`、`price_samples` 和必要的来源映射。只有明确启用历史采样时才长期保存 price_samples，并标记采样起点。

当前价与历史价使用不同缓存类别，键含商品类型/ID、地区、商店、来源和口径。目录别名匹配产生候选，不在缓存中保存模型猜测的 ID。

价格使用 metrics/fields，历史曲线使用 series，比较使用 table，商店链接使用 links。模型事实引用同一报价和来源，不由模型补造价格。主体负责所有最终排版。

## 6. 共享采集与订阅

注册 `price_watch` 采集器，按商品/地区/商店/来源口径规范化；周期及下限作为模块声明交给主体配置。订阅目标价、折扣、史低条件与通知模式不进入公共采集键。

多人关注同一价格只采集一次。一次来源批量请求可以包含多商品，但每项独立记录完整性；部分失败不能产生“降价到零”或清空旧价格。

匹配器输入快照、条件和上次匹配状态，输出事件与 DisplayDocument，不访问网络。促销轮次、跌破阈值及史低变化用稳定业务事件标识；持续满足同一条件不重复提醒。

愿望单若开放，先按权限取得商品集合，再让主体关联共享公开价格任务；愿望单内容和用户关注关系不进入共享公开事件。个人授权数据不得因为 SteamID 相同跨用户共享。

## 7. 并行边界与未定项

Dota 集成仅依赖公共能力 ID 和主体定义的响应，不依赖本目录的文件组织。该接口变化必须经公共契约协调，不在两个模块各维护一份响应类。

未定项：实际商品/地区覆盖、史低来源、默认地区、比较范围、用户授权可行性、轮询下限和通知规则。验证材料使用主体接口替身，不能直接引入另一模块的运行实例。
