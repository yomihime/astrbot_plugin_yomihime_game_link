# 单任务派发与交接模板

> 统筹从本模板创建任务卡，不把未填占位符直接发给实现者。
> 协作规则见[统筹协议](orchestration.md)，任务范围候选见[工作包目录](work-packages.md)。

## 1. 派发卡

```text
任务 ID / 标题：
角色与模型：实现者 Luna/Terra；独立审查 Sol
代码基线 / 工作目录或工作树：
公共契约版本及实际文件路径：

目标：用一两句话描述可观察结果。
本次明确交付：列具体能力、接口或文档，不写“完善整个模块”。
不包含：列最容易越界的相邻功能。

必读：架构章节、模块文档、实际接口及相关现有代码。
允许修改：精确文件或独占目录；验证材料路径。
禁止修改：共享 API、依赖、根配置及其他任务范围，除非明确列入允许范围。

编码前置条件：必须已存在的签名、schema、脱敏样例和产品决定。
集成前置条件：真实服务/模块/宿主可稍后就绪，明确未就绪时的交付状态。
已确定取舍：默认值、支持范围、错误行为；无依据项标明待确认。

输入/输出契约：具体类型、字段、错误及版本；给一个合法样例或文件路径。
核心路径：正常调用的起点与终点。
关键反例：至少列本任务真正相关的权限、缺失、失败或并发场景。
完成依据：可观察行为、必要验证、不能只靠代码存在判定的内容。
验证入口：当前可执行命令/运行条件；不存在时明确需要交付的验证入口。

阻塞处理：说明缺少哪项接口/证据，不自行创造旁路；继续可独立完成的部分。
交接位置：.coordination/handoffs/<任务 ID>.md
完成后：提交交接给统筹，等待 Sol 审查，不自行扩大范围或宣称项目完成。
```

## 2. 实现者交接

```text
任务 ID / 代码版本或明确 diff：
修改文件：
完成行为：
使用的契约版本：
验证：逐条写实际命令、结果、运行环境；未运行要明确。
关键反例结果：
仅使用替身的部分：
未验证的真实上游/宿主能力：
未完成项及原因：
接口/依赖变更请求：没有则写无，不隐式修改共享文件。
合入需要的清单/装配变更：由统筹执行，给精确映射。
已知风险：
建议状态：review_pending 或 blocked，不能直接标 final_checked。
```

## 3. Sol 审查交接

```text
任务 ID / 审查基线：
结论：通过本任务审查 / 需要修复
范围一致性：
发现：严重程度、路径/行、触发条件、影响、修复建议。
独立核对的验证证据：
尚未验证边界：
必须关闭的问题 ID：
对其他任务的影响：
```

## 4. 统筹派发自检

- 执行者不看聊天是否知道做什么、不做什么？
- 所有“现有接口”能否定位到真实文件和版本？
- 与其他活动任务是否存在可写路径重叠？
- 本次是否只是一个能独立审查的能力或子系统？
- 是否错误地把可选功能、授权待验证项分配为必须完成？
- 是否有能区分成功、失败、未实现和未验证的证据？
- 是否留下合入公共清单及实际装配的明确责任人？

任一关键项缺失时修订派发卡，不让实现者靠猜测补齐。
