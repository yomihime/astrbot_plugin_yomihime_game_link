# Dota 2 · 模块代码架构设计

## 1. 归属与范围

独占目录为 `modules/dota2/`，对应模块局部清单和模块验证材料由本模块维护。规范路由为 `/ygl dota2`。模块全局 ID 使用所属包 ID 加 `dota2`；包 ID 尚未冻结。

核心范围：玩家标识解析、绑定、公开资料、近期比赛和单场比赛。AI 分析、趋势统计和赛后订阅仍为可选，不因本文定义接口而默认开放。

本模块不修改主体公共 API、数据库表、调度器、通用渲染器、根包清单或其他模块目录。不直接调用 AstrBot 和消息发送接口。

## 2. 代码职责

```text
modules/dota2/
  manifest.json        局部静态声明，包清单引用它
  module.py            工厂、处理器绑定、生命周期
  models.py            玩家、比赛、查询口径、解析状态
  identity.py          用户输入到稳定玩家标识的转换
  capabilities.py      查询、绑定等能力处理器
  adapters/
    opendota.py        首选来源响应转换
    stratz.py          仅在启用备用来源时存在
  display.py           内部模型到主体展示协议
  subscriptions.py     仅在启用赛后订阅时存在
```

文件是职责落点，允许按规模合并。来源接口和认证方式需验证，不冻结具体外部字段。

## 3. 注册能力

以下 ID 是本模块建议的稳定内部 ID；除 `dota2` 和 `help` 外，具体操作名仍待统一。

| 能力 ID | 输入 | 输出 | 入口策略 |
| --- | --- | --- | --- |
| player.profile | 显式玩家或当前默认对象 | 公开玩家资料 | 允许自然语言，只读 |
| player.recent | 玩家、条数、模式筛选 | 近期比赛列表 | 允许自然语言，只读 |
| match.detail | 比赛 ID | 单场比赛 | 允许自然语言，只读 |
| account.bind | 玩家标识或候选选择 | 绑定结果 | 必须命令 |
| account.binding | 当前用户 | 当前绑定 | 必须命令 |
| account.unbind | 当前用户及明确目标 | 解绑结果 | 必须命令 |

内部身份解析不是独立账号管理 Tool。未指定玩家时通过主体 IdentityResolver 取得默认对象；结果不存在时不由模型猜测 ID。

能力分别声明数据源依赖；备用来源故障不能直接禁用仍可通过主来源运行的能力。

## 4. 内部数据模型

| 模型 | 主要语义 |
| --- | --- |
| PlayerRef | account_id、可选 SteamID64、显示名与来源；稳定 ID 不用昵称替代 |
| PlayerProfile | 昵称、头像引用、公开状态、可取得的段位和来源时间 |
| MatchSummary | 比赛 ID、开始时间、英雄、胜负、K/D/A、模式、时长 |
| MatchDetail | 阵营、比分、玩家、来源实际提供的统计 |
| ParseState | 未收录/基础数据/已解析/未知，字段存在性单独保存 |
| QueryScope | 默认条数、筛选、数据源和时间范围 |

SteamID 输入校验与转换在 identity/适配器内完成；不把任意 64 位数字直接当合法个人 SteamID。昵称搜索返回有来源的候选，选择会话由主体保存。

来源数据冲突时显示来源和口径，不逐字段拼出无依据的“完整比赛”。缺失段位或解析字段保持未知。

## 5. Steam 依赖边界

声明 Steam 的公开身份解析能力为可选依赖，只通过主体 DependencyInvoker 调用，继承原始来源。

优先顺序为显式对象 → Dota 独立绑定 → 主体允许的 Steam 派生身份。不能调用 Steam 的账号管理能力绕过 command_only，也不能读取 Steam 的配置、Grant 或集合。

无 Steam 模块时，稳定 account ID 的独立绑定和查询仍可运行；自定义个人页解析若缺少可用来源，只对该输入方式返回不可用。

Steam 换绑、停用后的派生关系由主体绑定服务处理，本模块不私自复制默认绑定来规避失效规则。相关最终产品行为仍待基本设计确认。

## 6. 存储与缓存

绑定与默认关系使用主体 AccountOperations。模块声明的集合可包括 `hero_catalog`、`player_snapshots`、`match_snapshots`；都在模块命名空间内。

公开缓存按玩家/比赛、来源、查询筛选、模型版本区分。玩家隐私状态变化按主体失效策略处理。保存的比赛事实不包含外部凭据，也不把短期缓存自动当长期统计数据库。

英雄目录资源通过主体 ResourceAccess 管理，中文名称映射与目录版本由本模块负责。

## 7. 展示与可选订阅

玩家资料映射为 fields/metrics，近期比赛映射为 table，比赛详情映射为分组字段和表格。模块只返回 DisplayDocument 与允许进入模型的事实，不绘图或发送消息。

若开放赛后订阅，注册按玩家与来源规范化的公开采集器，多人关注同一玩家共享一次采集。事件使用比赛 ID 和实际新增的数据状态区分；未解析到已解析是否再次提醒由订阅规则决定，不能每次轮询重复推送。

采集间隔声明为模块配置，实际执行交给主体；匹配函数不得额外查询网络。AI 分析不阻塞事实卡片，也不能虚构缺失时间线。

## 8. 并行对接与未定项

独立工作可依赖公共协议的受控替身验证模型和展示映射；替身属于模块验证材料，不写入主体 API 或生产入口。模块清单只提供声明，不修改包总清单。

未定项：近期默认数量及上限、模式筛选、昵称检索覆盖、来源额度、AI/赛后监听范围。对主体契约有新增需要时提出通用字段需求，由主体维护者统一更新，不增加临时私有接口。
