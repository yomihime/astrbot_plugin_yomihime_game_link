# 可派发工作包目录

> 本目录将架构映射为任务边界，不代表所有工作包已授权实施，也不是排期。
> 统筹必须按[派发模板](task-template.md)补齐实际基线、契约和验证入口后再分配。角色规则见[统筹协议](orchestration.md)。

## 1. 使用原则

工作包是范围上限，不是必须一次完成的大任务。每次派发只取表内一个明确交付，使用子任务 ID，例如 `C21-records` 或 `M-DOTA-recent`；不能让执行者同时完成一个工作包的全部相邻功能。

同一工作包的多个子任务不自动获得并行许可；共享文件仍然只能由一个活动任务修改。下列路径为建议落点，实际派发以现有树和显式文件清单为准。

## 3. 主体派发卡候选

### C00 公共契约

- 阅读：主体 §5–§10、§11 的装载边界。
- 归属：`api/`、`core/ports.py`、`tests/contracts/`。共享测试配置由统筹协调。
- 可拆交付：注册和上下文；展示和错误；存储/账号服务；调度/投递端口。单一契约维护者统一合入，不能多个任务同时改公共导出文件。
- 必须提供：真实可导入类型、合法及非法样例、明确的版本和最小调用示例；不实现游戏和完整后端。
- 完成依据：非法清单、未知必需块及参数类型错误可被判定；示例能使用同一套类型，模块不必再复制接口。
- 关键边界：可信来源不能只是模块可任意覆盖的参数；字段定义必须足以表达私人范围和失败状态。

### C10 注册与调用

- 阅读：主体 §5–§7、§12。
- 归属：`core/registry.py`、`core/invocation.py`、`core/policy.py`、`core/health.py`、`core/help_catalog.py`，以及 `tests/core/` 下对应文件。
- 可拆交付：注册冲突及快照；策略和调用；能力状态；两级帮助。每次选择一项并明确协作端口。
- 不包含：真实数据库、模块业务、宿主装饰器、生命周期具体取消实现。
- 完成依据：不硬编码游戏；总帮助与模块帮助范围正确；Tool 及嵌套调用不能执行 command_only 能力；用户未登录不污染模块健康状态。
- 关键反例：旧注册快照调用、重复路由、未启用模块、同名操作跨不同模块。

### C11 生命周期与任务所有权

- 阅读：主体 §6–§7。
- 归属：`core/lifecycle.py`、`core/task_scope.py`、`services/dependency_calls.py` 及对应验证文件。
- 可拆交付：模块状态与 epoch；受管任务取消；跨模块来源继承。一次只交付有明确端口的一项。
- 完成依据：停用后拒绝新调用，旧结果不能提交；重新启用不恢复旧 epoch；清理超时与在途发送状态准确。
- 关键反例：取消不可立即完成、依赖循环、内部来源提升、旧任务迟到。

### C20 数据库与主体仓储

- 阅读：主体 §9，基本设计 §6。
- 归属：`infrastructure/sqlite/`、`infrastructure/secret_store.py` 及 `tests/storage/`。一个子任务只取得明确仓储文件与相应迁移文件。
- 可拆交付：连接/事务和迁移；身份及授权仓储；采集/投递仓储；集合/缓存/资源索引；密钥存储。迁移编号与基础 database.py 由本工作包维护者独占协调。
- 不包含：用户命令、模块业务及调度时钟。
- 完成依据：实际存储满足唯一约束、所有者隔离和版本条件；事务失败不留下半套状态；密钥缺失不降级明文。
- 关键反例：并发更新、迁移失败、恢复后旧 sending、私人数据与共享数据混删。不得仅用内存替身宣称 SQLite 实现通过。

### C21 共用数据服务

- 阅读：主体 §5.3、§9。
- 归属：`services/configuration.py`、`services/records.py`、`services/cache.py`、`services/resources.py`、`infrastructure/files.py` 及各自验证文件。
- 可拆交付：配置 revision/敏感更新；集合权限；公开/私人缓存；受控文件资源。每次派发一个服务。
- 完成依据：模块只能操作自己的声明集合；私人资源不能因相同内容跨用户可见；已获知授权失效后不返回旧缓存。
- 不包含：具体 SQL 修改。仓储缺项向 C00/C20 提出请求。

### C22 身份与账号服务

- 阅读：主体 §6、§9，基本设计 §5。
- 归属：`services/identity.py`、`services/bindings.py`、`services/authorization.py` 及相应验证文件。
- 可拆交付：身份映射；默认绑定与派生；Grant 和登录代次。跨群、多账号等未确认行为必须先限定范围。
- 完成依据：默认公开对象解析不开放账号管理 Tool；重新登录和退出使旧结果失效；换绑不覆盖其他模块独立绑定。
- 不包含：B 站/Steam 游戏授权协议和真实来源登录。

### C30 通用展示

- 阅读：主体 §8。
- 归属：`presentation/`、`infrastructure/render_backend.py`、对应展示验证材料。公共 schema 仍归 C00。
- 可拆交付：协议校验和文本；通用布局及网格；通用曲线；事实投影。不允许一次派发“全部 UI”。
- 完成依据：合法文档不含游戏分支也能呈现；所有支持块有文本回退；未知块和资源异常有明确行为。
- 关键反例：大表分页、未知必需块、私人资源、图像失败。图片能力需实际渲染并查看产物，不能仅凭代码或文件存在判为成功。

### C40 共享采集与订阅

- 阅读：主体 §10，基本设计 §8.3。
- 归属：`services/scheduling/` 及对应验证文件。
- 可拆交付：注册和规范键；周期/并发；订阅命令服务；观察与匹配提交。数据库和模块匹配业务不在范围内。
- 完成依据：多人同信息共享一个在途采集；不同权限范围不合并；修改周期不重叠执行；匹配状态与待发内容共同提交。
- 关键反例：任务租约失效、部分采集、订阅修订、最后订阅取消、采集失败重试。不以每个用户独立轮询实现“共享”。

### C50 投递及结果出口

- 阅读：主体 §8.3、§10.5。
- 归属：`services/delivery/`，出口实现建议归 `services/output.py`，对应验证文件；该建议路径应在派发时明确。
- 可拆交付：持久化投递领取/回执；来源出口选择；摘要聚合。仓储和 AstrBot 发送由端口提供。
- 完成依据：命令、Tool、调度有不同出口；根调用只输出一次；unknown 不假冒 sent；取消订阅从摘要中剔除但不丢他人内容。
- 关键反例：发送前停用或授权撤销、响应丢失、恢复旧 sending。使用消息替身时必须标记未完成真实平台验证。

### C60 扩展包

- 阅读：主体 §11 及生命周期协议。
- 归属：`core/extensions.py` 及专属扩展验证材料。
- 可拆交付：静态清单及路径验证；兼容检查/工厂装载；包级更新状态。不能默认实现任意热替换或依赖自动安装。
- 完成依据：清单展示不执行模块业务代码；局部模块清单统一校验；包内模块独立启停；不兼容包与数据降级有明确拒绝状态。
- 关键反例：路径越界、同包部分失败、公共类型重复加载、包更新引发依赖影响。

### C70 宿主与集成

- 阅读：主体 §4、§12、全部待接入接口的真实代码。
- 归属：`main.py`、`bootstrap.py`、`integrations/astrbot/`；根包清单、根依赖及元信息仅由本工作包的统筹/集成维护者更新。
- 可拆交付：根命令和上下文；Tool 桥接；发送端口；管理鉴权；组件装配。宿主签名必须来自当前实际资料或源码，不能猜测。
- 完成依据：零模块可加载；`/ygl` 和 help 正确；实际组件接线且配置不双写；身份和管理鉴权不绕过。
- 关键边界：README 规定实际 AstrBot 集成在部署环境完成。无该环境时只能提交待部署验证，不得声称运行通过。

### C71 管理页面

- 阅读：主体 §12 及实际管理 DTO。
- 归属：`web/`、页面专属验证材料。根前端依赖由统筹合入。
- 可拆交付：模块总览/空状态；配置表单；能力状态和调度状态。页面不生成或持久化另一套配置模型。
- 完成依据：展示全由 DTO 驱动；敏感值不回显；周期配置与真实下次执行分开；不得写具体游戏页面分支。
- 关键反例：零模块、部分能力不可用、并发配置冲突。视觉产物需实际查看，权限不能只在前端隐藏。

## 4. 模块工作包

模块共同编码依赖：C00 实际契约与样例、明确的能力范围、允许使用的来源证据。集成依赖包括 C10/C11/C21/C22/C30/C70，订阅另需 C40/C50。

每次只选择一个能力或紧密相关的纯模型/适配任务；局部 manifest.json、module.py、models.py 的写权限仍需明确，不能同一模块同时多人改同一文件。

| 工作包 | 阅读 | 独占范围 | 合理子任务示例 | 完成依据与主要反例 |
| --- | --- | --- | --- | --- |
| M-FF14 | [模块文档](ff14.md)，需求 §4 | modules/ff14/、tests/modules/ff14/ | 角色解析；公开概览；指定条件成绩；展示映射 | 区域及指标不混用；无记录不判私密；静态图标失败可降级 |
| M-DOTA | [模块文档](dota2.md)，需求 §5 | modules/dota2/、tests/modules/dota2/ | ID 解析；公开资料；近期比赛；单场详情 | 无 Steam 仍支持独立 ID；未解析字段不编造；候选不静默选首项 |
| M-STEAM | [模块文档](steam.md)，需求 §6 | modules/steam/、tests/modules/steam/ | 公开身份；商品识别；当前价；可选历史价；价格采集/匹配 | 商品/地区口径一致；历史失败保留当前价；多人阈值匹配共享采集 |
| M-HBR | [模块文档](hbr.md)，需求 §7 | modules/hbr/、tests/modules/hbr/ | 图鉴模型；BOX 展示；限定授权链路验证；已验证字段查询 | 未验证链路不报成功；私人范围正确；缺失持有状态不判未持有 |

共同禁止：直接 SQL、直接发送、独立渲染、复制公共类型、按用户永久轮询、修改根依赖和其他模块。公开账号默认对象使用主体服务，不通过调用账号管理 Tool 实现。

Dota/Steam 公开身份契约由 C00 维护。Dota 可先用该契约替身独立验证；是否已经完成两模块真实集成必须单列。不得让两个执行者分别创造同名但不兼容的响应。

历史价、AI 分析、赛后订阅、市场、招募、HBR 导入等可选能力仅在派发卡明确选中时实现。真实上游授权验证与生产账号功能开发可分成不同任务，验证失败不是许可去猜接口。

## 5. 集成交接责任

模块实现者提供局部清单、工厂映射、所需依赖和契约版本，不改总清单。统筹/集成维护者完成总清单引用、装配及共享依赖处理，Sol 审查集成 diff，Astra 检查集成基线。

依赖没有准备好时，模块交付可以是“契约内组件已完成，等待指定集成依赖”，不能把连接主体的工作隐去。每项遗留工作必须写明确责任包和触发条件。

## 6. 当前可派发状态说明

本目录没有宣称任何包已 ready。当前项目仍为骨架，统筹应先核实实际代码；若 C00 尚不存在，首个实现任务应限于已授权的契约子任务。其余工作包只有在任务卡列出的编码前置条件满足后才可进入实现。
