# Yomihime Game Link · 怜的游戏连结 — 需求文档

> 整理日期：2026-09-13。
> 本文档描述“要实现什么、参考什么、整体实现思路是什么”，不包含实施排期、开发步骤、提交安排或测试计划。

## 1. 产品定位

Yomihime Game Link 是面向 AstrBot 的游戏与游戏平台信息查询插件，为不同游戏和平台提供统一、稳定、适合聊天场景的账号绑定、资料查询、战绩查询、价格查询、订阅推送与图片展示能力。

产品对象分为两类：

- 游戏：
  - 最终幻想 XIV（FF14）：角色绑定与 FFLogs 查询为核心。
  - Dota 2：玩家资料、近期战绩与单场对局查询为核心。
  - 炽焰天穹（Heaven Burns Red，简称 HBR）：B 服账号登录、个人资料、持有 BOX 与高分挑战查询为核心。
- 游戏平台：
  - Steam：平台账号绑定、游戏检索、当前价格、折扣与历史低价查询为核心，并支持自然语言调用。

Yomihime Arcade 仍用于未来的 Bot 聊天游戏，不属于本插件。

## 2. 总体需求

### 2.1 统一入口

- 仅提供 `/ygl` 作为顶层命令入口，游戏与游戏平台功能统一使用 `/ygl <模块名> <操作> [参数]`，例如 `/ygl dota2 …`。不提供独立的游戏快捷命令或为缩短输入而增加缩写别名。
- 命令数量尽量少，名称以清晰、稳定为优先，不以缩短输入长度为目标；相近功能优先通过参数区分。
- 高频功能应有明确的固定命令，不依赖 LLM 才能使用。
- 初步确定：账号与周期任务（订阅）相关功能必须通过命令，包括查看相关状态；其他功能允许自然语言调用。自然语言提出账号或订阅请求时给出对应命令，不直接执行。
- `/ygl help` 只展示必须通过命令使用的操作，以及各模块的 `/ygl <模块名> help` 入口；不展开普通查询命令。
- `/ygl <模块名> help` 展示指定模块全部已注册命令，包括普通查询命令，并标明必要权限与不可用状态。帮助内容由注册信息生成。
- 可将允许自然语言调用的只读查询暴露为 AstrBot LLM Tool，但命令与 Tool 必须复用同一套业务能力和结果模型；账号和周期任务能力即使只读也不暴露为 Tool。普通公开查询使用默认绑定不等于账号管理。
- Steam 价格查询必须支持自然语言调用，例如“艾尔登法环现在多少钱”“双人成行史低多少”“这个 Steam 链接打折了吗”。
- 登录、凭据、绑定修改等敏感操作不得交给 LLM 自行决定，也不得把凭据传入模型上下文。

### 2.2 用户与绑定

- 用“消息平台 + 平台用户 ID”识别聊天用户，避免 QQ 等消息平台与 Steam 等游戏平台在概念上混淆，也避免不同用户串绑。
- 支持账号或角色关联的游戏、游戏平台都应提供查看绑定和解除绑定。
- “绑定”表示保存默认查询对象，不默认表示已经验证账号所有权。
- 查询显式指定对象时使用该对象；未指定时使用当前用户的默认绑定。
- 数据模型应允许以后扩展同游戏或同游戏平台的多账号，但是否首版开放多账号切换待确认。
- 游戏平台账号可以被关联游戏复用。例如，Dota 2 可以从已绑定的 Steam 账号派生玩家标识，不要求用户重复绑定；Dota 2 专属设置和 Steam 平台设置仍分别保存。

### 2.3 展示与反馈

- 常用查询优先提供适合 QQ 阅读和转发的图片卡片，同时保留文本回退。
- 图片应包含查询对象、关键指标、数据来源或口径、更新时间。
- 耗时查询可以先回复“正在查询，请稍等”，最终结果不得因中间提示而丢失。
- 明确区分参数错误、未绑定、对象不存在、数据不公开、无记录、数据未解析、认证失效、限流和上游故障。
- 不把原始 JSON、异常堆栈或敏感字段直接发送给用户。

### 2.4 数据与隐私

- 用户绑定、授权状态和缓存应保存于 AstrBot 插件数据目录，不写入源码仓库。
- 密钥、Token、Cookie、二维码内容和设备标识不得进入普通日志或聊天上下文。
- 公开数据缓存与用户授权数据缓存必须隔离；个人账号数据不能跨用户复用。
- 第三方代码、数据、图片和字体分别确认许可，不因仓库公开就默认允许复制或分发。

### 2.5 可选订阅与推送

推送作为可选能力纳入需求，但默认关闭，只在用户或群聊主动订阅后发送。

支持的内容类型：

- 游戏活动日历：指定游戏的版本活动、限时活动、赛事或其他已接入日历事件。
- 游戏平台活动日历：Steam 等平台的大型促销、主题节、新品节、免费周末等公开活动。
- 游戏折扣：关注游戏开始打折、达到目标价格、达到指定折扣或刷新史低时提醒。

推送要求：

- 支持订阅、查看订阅、修改和取消订阅。
- 订阅明确记录内容类型、目标游戏或平台、接收会话、创建者、地区、时区和筛选条件。
- 折扣订阅允许按指定游戏、愿望单、目标价格、最低折扣和“达到史低”筛选；依赖个人愿望单时需要 Steam 账号绑定及相应可见性或授权。
- 活动日历允许订阅单个游戏、多个游戏或整个平台；事件时间以用户或会话时区显示。
- 支持即时提醒和摘要两种模式，具体默认模式待确认。
- 同一活动或同一轮价格变化不得重复刷屏；只有达到新的订阅条件或状态发生有意义变化时再次提醒。
- 推送内容显示触发原因、地区/币种、数据来源、更新时间和取消订阅入口。
- 上游数据不完整或推送失败时不得将消息标记为已经成功送达。
- 模块通过向主体注册采集调度实现订阅，由主体统一管理任务；同一公开信息的多个用户订阅共享每轮采集，采集后分别匹配条件，不按用户重复轮询。
- 共享范围必须包含来源、对象、地区等数据口径；用户授权数据不得跨用户合并采集。用户阈值和通知方式不应拆分同一公开信息的采集任务。
- 采集周期必须可配置，并与即时/摘要等通知周期分开；具体配置层级、来源限流和任务恢复行为由基本设计规定。

## 3. 主体、注册制与插件页面

### 3.1 主体定位

- 主体是与 AstrBot 对接的最小运行时，负责模块注册、生命周期、统一页面、配置、身份、存储、命令与 LLM Tool 对接、订阅调度和结果发送。
- 主体不包含 FF14、Dota 2、Steam、HBR 等具体业务，也不写死任何游戏名称、配置字段或功能按钮。
- 没有任何游戏或游戏平台模块注册、或者所有模块都被关闭时，主体仍能正常加载和运行。
- 空载状态下不提供游戏查询功能，只保留插件说明、模块管理页面和必要的状态信息，并明确提示“当前没有已启用功能”。
- 新增游戏或游戏平台时，应通过注册模块接入，不修改主体的页面布局和通用对接逻辑。
- 主体提供公开、版本化的扩展注册契约，允许第三方独立扩展包在不修改主体仓库的情况下注册游戏或游戏平台能力。

### 3.2 模块分类与开关

- 每个模块必须声明分类：`game`（游戏）或 `platform`（游戏平台）。
- 每个游戏或游戏平台都是独立模块，拥有独立启用开关。
- 管理页面可以按“全部、游戏、游戏平台”筛选模块。
- 关闭模块后，其命令、自然语言 Tool、后台任务、订阅触发器和外部请求均停止工作。
- 关闭模块不自动删除配置、账号绑定、订阅和缓存；涉及清除数据时必须提供单独操作和明确确认。
- 重新启用模块时恢复仍然有效的配置和用户数据，并重新检查依赖与连接状态。
- 模块缺少必填配置或依赖时不能表现为“正常可用”，页面应显示“需要配置”或“依赖缺失”。
- 能力级依赖或配置缺失只影响相关能力；模块状态由能力可用状态汇总。单个用户未绑定或授权失效不应被记为模块全局故障。

模块状态至少包括：

- 未启用。
- 需要配置。
- 正常运行。
- 部分能力不可用。
- 连接异常。
- 模块错误。

### 3.3 注册内容

每个游戏或游戏平台实现自行向主体注册所需内容，主体只读取注册结果并完成展示和对接。注册信息至少覆盖：

| 注册内容 | 用途 |
| --- | --- |
| 基本信息 | 唯一模块 ID、分类、名称、图标、说明、版本和帮助链接 |
| 能力清单 | 查询、绑定、图片生成、自然语言调用、订阅推送等用户可见能力，以及必须命令/允许自然语言的调用策略 |
| 命令 | `/ygl` 下的模块路由名、操作名、参数说明、权限与处理入口 |
| LLM Tool | Tool 名称、用途、参数结构和只读/写入性质 |
| 配置结构 | 字段类型、默认值、是否必填、是否敏感、选项、校验和说明 |
| 数据源 | 数据源名称、用途、凭据需求、连接状态和说明链接 |
| 账号与绑定 | 支持的绑定对象、稳定标识、公开查询和授权范围 |
| 推送类型 | 可订阅事件、筛选条件、默认方式和消息生成入口 |
| 状态检查 | 配置完整性、依赖、数据源连接和功能健康状态 |
| 生命周期 | 模块启用、停用、重载和主体退出时需要执行的动作 |
| 依赖关系 | 必需模块、可选模块和可降级能力 |

注册约束：

- 模块 ID、命令和 Tool 名称必须可检测冲突；冲突模块不得静默覆盖已有注册。
- 配置项和敏感凭据由主体统一保存与脱敏，模块只能通过受控接口读取自身配置。
- 模块只能注册声明过的后台任务和推送事件；停用时必须能由主体统一取消。
- 注册失败只影响当前模块，不能导致主体和其他模块无法加载。
- 模块可以声明对其他模块的可选依赖。例如 Dota 2 可复用 Steam 身份，但 Steam 关闭时仍可保留独立的 Dota 2 绑定能力。
- 内置模块与第三方扩展包使用同一注册契约和页面展示规则，不为内置模块保留绕过注册表的私有入口。
- 注册契约必须有明确版本；扩展包声明支持的主体版本或契约版本，不兼容时拒绝启用并显示原因。
- 第三方扩展包使用独立且稳定的命名空间保存配置、绑定、缓存和迁移版本，避免与主体或其他模块冲突。
- 一个第三方扩展包可以包含任意数量的模块；包作为安装与代码版本单位，模块仍独立注册、配置、启用和停用。
- 扩展包注册时声明作者、来源、版本、许可证、所需网络目标、敏感配置、存储、后台任务和消息发送能力，供管理员启用前查看。
- 第三方扩展包安装后可以出现在页面中，但未经管理员启用不得注册用户命令、LLM Tool、定时任务或主动推送。
- 卸载第三方扩展包不得破坏主体；遗留配置和用户数据应被标记为未挂载数据，由管理员决定保留或清除。
- 主体与第三方扩展包运行在同一 Python/AstrBot 进程时不能视为安全沙箱，页面必须提示管理员只安装可信来源的扩展包。

### 3.4 插件管理页面

主体提供独立的插件管理页面，不依赖 AstrBot 通用插件配置表单承载完整管理体验。页面内容由注册表动态生成，不为具体游戏维护独立的硬编码页面。

| 页面区域 | 展示内容 | 内容来源 |
| --- | --- | --- |
| 顶部总览 | 主体状态、已注册模块数、已启用数、异常数 | 主体与注册表 |
| 分类筛选 | 全部、游戏、游戏平台 | 模块分类 |
| 模块卡片 | 图标、名称、分类、版本、开关、状态、能力摘要 | 模块基本信息与状态 |
| 模块详情 | 功能说明、命令、自然语言能力、账号绑定、推送能力 | 模块能力注册 |
| 配置区域 | 普通配置、数据源、凭据和字段校验 | 模块配置结构 |
| 状态区域 | 配置完整性、依赖、连接结果、最近错误和更新时间 | 模块状态检查 |
| 数据管理 | 缓存、绑定和订阅的数量摘要及受控清理入口 | 主体存储与模块声明 |
| 扩展信息 | 内置/第三方标识、作者、来源、许可证、兼容性和能力声明 | 扩展包清单 |

页面交互要求：

- 模块卡片上的开关用于启用或停用模块；状态与开关必须是两个独立概念。
- 模块详情只显示该模块注册过的配置和能力，不展示无关的通用占位字段。
- 页面包含主体设置与模块管理两个层次；主体设置只放全局运行时配置，游戏或游戏平台配置始终归属对应模块。
- 敏感配置默认隐藏，页面不得回显完整密钥、Token 或 Cookie。
- 配置保存前执行模块注册的校验；错误信息指向具体字段，并保留用户尚未提交的内容。
- 提供模块级连接检查，但只检查该模块声明的数据源。
- 页面清楚区分“已保存配置”“配置有效”“模块已启用”“功能当前可用”。
- 零模块时显示空状态和接入说明，不显示 FF14、Dota 2、Steam 或 HBR 的空卡片。
- 页面本身不承担个人用户登录流程；需要用户身份的扫码或授权仍在对应聊天用户的私聊或模块声明的安全流程中完成。
- 页面沿用 AstrBot 管理端身份和权限，不另建一套独立管理员账号；所有页面数据和管理操作都必须经过管理端权限校验。
- 第三方扩展详情必须在启用前展示来源、兼容状态和能力声明，并对未知来源给出信任风险提示。

### 3.5 统一对接

- 主体根据启用模块的注册信息生成命令路由、帮助内容和 LLM Tool 清单。
- 自然语言只能调用当前已启用且状态允许的 Tool；停用模块不应继续出现在可调用能力中。
- 主体为模块提供消息用户身份、配置、存储、HTTP、缓存、渲染、订阅和日志等通用服务接口。
- 主体在调用上下文中保留可信来源，统一检查命令、LLM Tool、调度与管理操作的权限；内部调用不能将自然语言来源提升为命令来源。
- 模块返回主体约定格式的结构化结果或错误，适配主体通用展示协议；主体负责文本、图片、等待提示和错误展示，不添加具体游戏的专属展示分支。
- 命令、LLM Tool 与订阅复用业务能力，但由主体选择不同结果出口：命令直接回复、Tool 返回允许进入模型的事实、订阅生成投递记录，避免重复发送。
- 帮助命令和插件页面使用同一注册信息，避免页面、命令帮助与真实能力不一致。
- 第三方扩展包通过稳定的注册入口连接主体服务，不直接修改主体内部注册表、页面状态或其他模块数据。

## 4. FF14

### 4.1 要实现什么

核心功能：

- 绑定、查看和解绑 FF14 角色，绑定信息包含角色名、服务器和区域。
- 支持国服与国际服，并在结果中明确显示区域和服务器，避免同名角色串查。
- 查询角色公开 FFLogs 概览。
- 查询指定副本、难度或分区的公开记录与百分位。
- 支持 rDPS、aDPS、nDPS、cDPS、pDPS 等指标，并始终显示当前指标口径。
- 展示角色、职业、副本/分区、难度、版本或分区信息、成绩与更新时间。
- 正确区分“角色不存在”“没有公开记录”“报告私密不可见”和“接口暂时不可用”。

可选扩展：

- 物品资料与图标。
- Universalis 市场价格。
- 国服招募板查询。
- 活动日历。

石之家登录、签到、房屋、攻略聚合、微博和娱乐功能不属于当前确定需求。

### 4.2 参考什么

- [AstrBot 塔塔露插件](https://github.com/jawwe/astrbot_plugin_tataru)：参考命令体验、国服/国际服处理、FFLogs 指标展示和文本/图片回退；不照搬其全部功能或单文件结构。
- [FFLogs v2 API](https://www.fflogs.com/api/docs)：角色和公开战斗记录的主要数据源。
- [XIVAPI v2](https://v2.xivapi.com/docs/welcome/)：职业、物品、图标等静态资料的候选数据源，不将其视为完整角色数据源。
- Universalis：市场数据候选来源。

### 4.3 实现思路

- 使用角色名、服务器与区域共同定位角色，条件允许时保存数据源返回的稳定角色 ID。
- FFLogs 访问封装为独立数据适配器，插件内部使用统一角色和战绩模型，避免外部 GraphQL 字段直接渗透到命令层。
- 指标、区域、分区、难度等查询条件进入缓存标识，防止不同口径结果混用。
- 静态资料与战斗记录分开获取；某一辅助来源失败时，尽量保留仍可用的核心结果。
- 查询结果由统一模型分别渲染为文本和图片卡片。

## 5. Dota 2

### 5.1 要实现什么

核心功能：

- 识别 32 位 account ID、64 位 SteamID 和标准 Steam 个人页链接。
- 支持昵称搜索；出现重名时返回候选，不静默选择第一项。
- 绑定、查看和解绑 Dota 2 玩家。
- 查询玩家资料，包括昵称、头像、稳定 ID、公开状态和可取得的段位信息。
- 查询近期对局，展示比赛 ID、时间、英雄、胜负、K/D/A、模式和时长。
- 查询单场对局，展示双方比分、阵容及当前数据源实际提供的统计。
- 英雄名至少提供中文或中英对照，不只显示内部英文键。
- 对私密资料、尚未收录、尚未解析和字段缺失给出清楚说明。

可选扩展：

- 最近 N 场胜率、KDA、英雄池、分路和趋势统计。
- 基于现有事实字段的单场或近期 AI 分析；事实查询不能依赖 LLM 成功。
- 赛后监听和主动推送；订阅范围、重复投递与平台主动消息能力需要单独定义。

### 5.2 参考什么

附件插件没有附带许可证，且声明的测试目录未包含在压缩包中，因此在来源和授权确认前只作为行为参考，不直接复制代码。

- 先把各种 Steam 标识归一化为稳定 account ID，再由绑定和查询能力使用。

- 明确记录字段是否存在和比赛是否已解析；统计与 AI 只能使用真实可用字段，不补写经济曲线、团战或装备时间线。
- AI 分析作为事实卡片之后的可选增强，并允许部署者关闭或选择 AstrBot Provider。
- 图片卡片展示高频事实，较长的分析内容使用独立消息，避免一张图信息过载。

## 6. Steam 平台

### 6.1 要实现什么

#### 个人账号绑定

- 像 Dota 2 一样支持绑定、查看和解绑 Steam 个人账号。
- 支持 SteamID64、标准个人资料链接和自定义个人资料链接；昵称搜索结果不唯一时返回候选。
- 展示公开可见的昵称、头像、SteamID、个人资料链接、账号状态，以及可取得的游戏数量和游玩时间摘要。
- 用户说“我的 Steam”“我的愿望单”“我库里的游戏”时使用其 Steam 平台绑定。
- 公开资料绑定不等于账号所有权验证；需要访问非公开游戏库、愿望单或个性化商店信息时，应采用明确授权，而不是索要账号密码或 Cookie。
- Steam 绑定可供 Dota 2 等关联游戏读取稳定身份；从 SteamID64 派生 Dota 2 account ID 时应向用户说明关联结果。

#### 游戏识别

- 支持使用中英文游戏名、Steam App ID 和 Steam 商店链接查询。
- 支持常见简称或译名匹配；结果不唯一时返回候选游戏，不能把模糊匹配结果直接当成唯一答案。
- 明确区分本体、DLC、原声集、试玩版、不同版本和捆绑包，避免价格对象混淆。

#### 当前价格与折扣

- 查询游戏在指定地区的原价、当前价、折扣比例、币种和促销截止时间（数据源提供时）。
- 默认地区和货币可配置；自然语言中出现“国区”“日区”“美元”等表达时覆盖默认值。
- 明确显示查询地区、币种、数据来源和更新时间。
- 提供对应 Steam 商店链接，最终购买价格和可购状态以商店页面为准。
- 免费游戏、尚未发售、已下架、地区不可用和暂时无价格必须分别说明。

#### 历史价格

- 数据源允许时展示 Steam 历史最低价、最低折扣、发生时间，以及当前价格是否达到或接近史低。
- “Steam 史低”“全网史低”和“当前全网最低价”必须明确区分，不把不同商店、地区或货币的价格混为一谈。
- 历史数据需要显示覆盖地区、商店范围和统计时间范围；数据不足时只返回当前价，不推测史低。
- 价格曲线作为图片卡片的可选展示，基础查询至少给出当前价与可用的史低摘要。

#### 自然语言调用

- 用户无需记忆固定命令，可以直接询问游戏价格、折扣和史低。
- 支持的典型表达包括：
  - “艾尔登法环现在多少钱？”
  - “博德之门 3 国区打折了吗？”
  - “双人成行史低多少，现在是史低吗？”
  - “帮我查这个链接的价格：<Steam 商店链接>”。
  - “A 和 B 现在谁更便宜？”
- LLM 只负责把自然语言解析成游戏、地区、货币、查询类型等结构化参数，价格事实必须由数据服务返回。
- 游戏名或地区存在歧义时应向用户确认或返回候选，不允许模型自行编造 App ID、价格或史低。
- 同一能力同时保留 `/ygl steam price` 等固定命令，确保未启用 LLM 时仍能查询；模块路由和操作名的最终规范由基本设计统一定义。

#### 可选扩展

- 多款游戏当前价格对比。
- 当前特惠榜单与按折扣、价格、类型筛选。
- 用户关注列表、目标价格提醒和限时免费提醒，并接入统一订阅推送能力。
- 与已绑定 Steam 账号的愿望单或游戏库联动；这属于平台账号功能，不是公共价格查询的前提。

### 6.2 参考什么

- 小黑盒 Steam 价格查询：参考中文游戏检索、当前价/原价/折扣/史低的集中展示和移动端阅读体验；不默认依赖或逆向其非公开接口。
- [Steamworks Web API](https://partner.steamgames.com/doc/webapi_overview)：Steam 公共服务与认证边界的官方说明。
- [IStoreService](https://partner.steamgames.com/doc/webapi/IStoreService)：Steam 应用目录和变更信息候选来源；部分能力需要 Web API Key。
- Steam 商店公开页面或商店数据接口：当前地区价格、折扣和商店链接的主要候选来源，具体接口需与使用条款及稳定性一并确认。
- [IsThereAnyDeal API](https://docs.isthereanydeal.com/)：历史低价、价格历史和多商店报价的候选来源；接入时必须遵守其注册、署名、链接与数据使用条款。
- SteamDB 只用于人工核对展示口径；其公开说明当前没有通用 API 且禁止自动抓取，因此不作为插件数据源。

### 6.3 实现思路

- Steam 平台账号使用 SteamID64 作为稳定标识，自定义个人资料名和昵称只用于解析或展示。
- 平台绑定服务与价格查询服务分离；公共价格查询无需登录，个人游戏库、愿望单和个性化信息根据公开状态或授权决定可用范围。
- Dota 2 通过共享的 Steam 身份映射读取 account ID，但仍保留自己的玩家绑定、查询偏好和业务模型。
- 先将游戏名称、别名、App ID 或商店链接归一化为明确的 Steam 商品，再查询对应地区的价格。
- 建立统一价格模型，区分原价、当前价、折扣、Steam 史低、全网史低、地区、币种、商店和采集时间。
- 当前价格适配器与历史价格适配器分离；历史来源不可用时仍能正常返回 Steam 当前价。
- 将只读价格服务注册为 AstrBot LLM Tool，参数包含查询词/App ID、地区、货币、是否需要历史价和比较对象；固定命令调用同一服务。
- 对游戏目录和短期价格做合理缓存，但结果始终携带更新时间，促销临近结束时使用更短缓存。
- 历史价格可以来自有明确 API 与使用许可的第三方服务，或由本项目从接入后开始自行积累；自行记录的数据不能冒充第三方完整历史。

### 6.4 已知约束

- Steam 商品价格具有地区、币种、包体和用户资格差异，Bot 返回的是指定口径下的参考价格，不代表所有账号的结算价。
- 捆绑包可能根据用户已拥有内容产生个性化价格；未接入用户授权时不能声称得到个人专属包价。
- Steam 官方公开能力不等于完整历史价格数据库，史低功能依赖合规第三方数据或长期自行采样。
- 小黑盒的产品体验可以参考，但其数据、接口、图片和实现不能在没有授权时直接复制。

## 7. 炽焰天穹（HBR）

### 7.1 要实现什么

#### B 服登录

- 提供统一入口下的登录操作，例如 `/ygl hbr 登录`，生成二维码供用户扫码登录 B 站账号，不另设中文独立触发命令。
- 提供重新登录操作，例如 `/ygl hbr 重新登录`，用于替换当前用户卡住或失效的登录流程。
- 提供登录状态查询和退出登录。
- 登录流程识别待扫码、待确认、成功、过期、取消和失败状态。
- 登录会话按用户隔离；重新登录和退出只影响当前用户。
- 不收集 B 站账号密码，也不把普通 B 站网页登录态未经验证地当作 HBR 游戏授权。

#### 个人信息

- 提供个人信息查询，例如 `/ygl hbr 我的`。
- 展示从实际可用接口取得的游戏昵称、玩家 ID、等级或进度等稳定字段。
- 可附带 BOX 摘要；BOX 图片失败不应导致个人资料查询整体失败。

#### 持有 BOX

- 提供 BOX 查询，例如 `/ygl hbr box`，从已登录账号读取持有风格并生成图片。
- 参考用户提供的目标 Bot 截图，BOX 图采用紧凑的全图鉴头像网格：
  - 已持有风格正常显示或高亮。
  - 未持有风格保留位置并明显压暗。
  - 固定排列便于不同用户或不同时间的 BOX 直接比较。
  - 图中显示“持有数 / 当前图鉴总数”和完成率百分比。
  - 版面适合 QQ 消息内查看，图鉴扩充后允许缩放、分组或分页。
- 结构化 BOX 数据应包含稳定风格 ID、角色/风格名称、稀有度、持有状态，以及接口确实提供时的突破信息。
- 显示同步时间和数据版本；上游暂时不可用时可展示明确标注时间的最近缓存。
- BOX 属于个人账号数据，默认仅本人可查；可另行提供由本人主动生成的分享图。

#### 高分挑战

- 提供高分查询，例如 `/ygl hbr 高分`。
- 展示挑战名称或赛季、最高分、档位/排名、使用队伍与更新时间，以实际可取得字段为准。
- 默认查询当前或最近一期；数据源支持时允许指定历史期数。

#### 公共资料扩展

- 角色、风格与技能检索。
- 攻略索引或受控外链。
- 随机角色或风格。
- 卡面提取与卡面生成；具体含义需更多目标 Bot 样例才能定义。

娱乐台词类命令不属于当前需求。

## 8. 共同实现思路

- 主体通过注册表装配当前启用能力；AstrBot 入口只负责识别命令、自然语言 Tool 调用、当前消息平台用户和发送结果，具体业务由 FF14、Dota 2、Steam、HBR 等注册模块提供。
- 各游戏与游戏平台通过数据适配器访问外部服务，并转换为项目内部模型；命令层、LLM Tool 和图片渲染不直接依赖外部接口原始结构。
- 绑定、授权、缓存、错误映射、HTTP 超时/限流处理和图片输出作为共用能力，游戏专属字段仍由各模块维护。
- 订阅服务使用统一的事件和投递模型，游戏活动、平台活动与价格变化由各自数据适配器转换为可去重的推送事件。
- 正式数据存储采用可迁移的结构化存储；用户身份、游戏对象、授权信息和缓存明确分区。
- 所有核心结果先有可读文本表示，再生成图片增强，保证字体、渲染或平台传图失败时仍可使用。
- 外部服务变化时优先修改对应适配器，不改变用户命令和内部结果语义。

## 9. 范围边界

- 不照搬塔塔露、Dota2 附件插件或目标 HBR Bot；它们用于确认用户需求和交互习惯。
- 不把 LLM 生成内容当作战绩事实。
- 不在数据缺失时推测或伪造字段。
- 不默认实现 FF14 私人报告 OAuth、石之家个人功能或网页登录 Cookie 功能。
- 不默认实现 Dota 2 主动推送，也不让 AI 分析阻塞基础查询。
- 不默认向任何用户或群聊发送活动、平台或折扣消息；所有推送必须来源于可查看、可取消的订阅。
- 不通过抓取小黑盒或 SteamDB 的非公开页面实现 Steam 价格查询。
- 不把某一地区、商店或包体的价格表述为无条件适用于所有用户的价格。
- 不在授权流程未经验证时宣称已经支持 HBR 账号数据。
- 不打包来源或许可不明确的第三方游戏素材、字体和数据库。
- 不允许具体游戏或游戏平台绕过注册表，直接向主体页面写入专属配置、按钮或状态逻辑。
- 主体空载运行是受支持状态，不把“没有启用模块”视为插件故障。
- 不承诺在同一进程内对恶意第三方 Python 扩展提供强安全隔离；扩展来源与权限声明必须对管理员透明。
