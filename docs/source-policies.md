# Trusted external source policies

Core accepts external sensitive configuration only with an explicitly built, exact-manifest source policy. Module declarations alone do not grant secret use. Pair `--external-source-policy-package` with the same `--external-page-package` when building a reviewed package. The output `external-source-policies.json` contains declarations and public protocol descriptors, never credentials. Runtime validates the entire captured manifest digest, owner, source host, sensitive field and credential group before attachment.

Static credentials use encrypted existing configuration/CAS storage. `SourceCredentialPolicy(kind="static", injections=..., optional=...)` is Core composition, outside the public module SDK. Each injection fixes source/host/path/method, header or top-level JSON, token/subject and optional Bearer prefix. A wildcard matches one bounded ASCII path segment, never a URL or arbitrary expression. Caller collisions are rejected. Only an absent optional credential permits anonymous access; invalid/unreadable configured material fails. Every request verifies the current secret reference and authority. Existing OAuth client credentials remain supported.

Authorization descriptors declare finite trusted requests, response paths and closed state interpretation. Core's runner captures temporary tickets and final credentials; ordinary modules receive only safe status/subject. UI-driven polling is bounded, no background network polling survives the page. Binding includes authenticated actor, page lineage, owner, runtime, epoch and expected revision. Cancel/expire/revoke/unload fence late responses, and final capture uses the same guarded encrypted CAS update. The runner's QR image is privileged management data and must not appear in ordinary getters, logs, caches or model facts.

`SourceDeclaration.requests_per_hour` and `request_budget_config` declare a positive rolling-hour budget; config absence/empty restores its default, nonpositive values fail. `scope.http.budget(source_id)` returns safe source_id/requests_per_hour/used/remaining/next_available_at. The Core SQLite ledger is shared by trusted host across manual/tool/subscription requests and process reopen. Actual explicit transport attempts, including retries, are charged; cache hits are not. RPM and RPH reserve atomically. 429 Retry-After seconds or HTTP date persists a cooldown. `SourceHttpError.next_available_at` lets the scheduler release the lease and defer instead of sleeping while holding it. Key replacement and restart do not erase attempts.

`authorization_only=True` prevents normal bound SDK HTTP from reading an authorization response. This declaration does not grant authorization rights: the trusted pinned descriptor, current management proof and Core-only request path remain required. Public image preview similarly remains inside its current WEB_PUBLIC invocation until resources and PNGs are checked; it never impersonates a chat command.

A build-selected policy may additionally declare `capability_timeouts: {owner: {capability: seconds}}` for exact declared PUBLIC/READ_ONLY WEB_PUBLIC targets. Values must be finite and within (0,90]; unspecified targets retain existing defaults. Host route withdrawal removes its external timeout. The same ceiling reaches Host proof and Core invocation, and actual JWT expiry, spent entry time, generation and final publication checks can only shorten it. This is trusted build composition, never a request or module-self-selected timeout. Raw selected policy bytes and the entire external page projection are rechecked before archive publication; a change leaves the previous artifact intact.
