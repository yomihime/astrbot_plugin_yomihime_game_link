# FF14 国服新闻：移动版网页截图

消息顺序为标题、简述、原文链接、图片。图片直接截取官网 `indexm.html` 的移动版文章，从页面顶部到 `#newsCon` 正文末尾，保留官网标题、日期和正文图片，排除下方社交与版权页脚。不重排正文，不以设计卡片代替网页截图。

## 运行环境

在运行 AstrBot 的同一 Python 环境中安装可选依赖，并为运行 AstrBot 的同一系统用户安装 Chromium：

```sh
python -m pip install -r requirements-news-screenshot.txt
python -m playwright install chromium
```

Linux 还需安装 Playwright 所需的系统库，并允许 Chromium 沙箱正常运行。插件不会运行安装命令、下载浏览器、关闭 TLS 验证或关闭浏览器沙箱。已经安装兼容 Playwright/Chromium 的环境无需重复安装。缺依赖时插件仍可启动、采集和发送文字；本轮未改 AstrBot 源码。

## 简述与失败行为

- 每个新新闻 ID 都读取官网详情；首次基线不批量读取历史正文。
- 简述按原文顺序抽取前 3 个有意义的句段，最多 200 字，去掉独立问候、重复标题和落款。它是正文摘录，不是 LLM 改写；不消耗模型额度。没有可用正文时提示查看原文。
- 详情请求失败仍按原有采集失败处理，不推进去重状态。当前运行期会有界缓存已取得的正文摘录，限流或超时重试时继续剩余详情；缓存不跨 Host 重启持久化，重启后重新采集但不会提前标记为已推送。
- 截图失败是可选呈现失败，发送完整文字与链接，并提示“网页截图暂不可用，请查看原文。”不会发送错误页或改回新闻卡片。
- 采用 485 CSS 像素宽、DPR 1 的移动视口。正文截图超过 8192 像素高或 PNG 超过 1 MiB 时降级文字，不静默截断正文。
- 同一新闻 ID 仍只推送一次；截图失败后不会另外补发图片。发送结果不确定时不自动重发。真实 IM 最终效果需目标平台验证。

## 实现边界

新闻用 `UnknownBlock(kind="official_mobile_screenshot_v1")` 请求可选截图，沿用既有可选扩展槽及其明文回退，不改变 SDK 数据结构。普通链接不会触发截图。Core 识别标记并只接受固定官网移动文章 URL 和数字新闻 ID；没有任意 URL、DOM selector、脚本或浏览器参数入口。其他公开订阅保留原卡片行为。

截图通过公开订阅现有的发送前图片 hook 执行；成功后才移除截图回退提示。PNG 不进入采集数据库、不作资源 ID 或授权凭据。截图后继续检查模块 epoch、订阅 revision、发送目标和发送 claim。取消会传递到截图任务并关闭浏览器。

浏览器不使用用户配置、登录态、Cookie 或下载目录。页面 HTTP 请求由匿名 HTTP 客户端代理，校验精确官方资源域名、HTTPS、端口、公网 DNS 地址，禁止自动重定向；不允许任意第三方脚本、内网地址、WebSocket 或 Service Worker。隔离浏览器另设不可用代理并禁用 QUIC 与非代理 WebRTC UDP，避免浏览器自行直连；这不替代系统级浏览器沙箱。总时限 35 秒，单响应最多 4 MiB、累计最多 24 MiB，最多 100 个请求，截图串行执行，同一文章与标题的成功截图在内存中复用 2 分钟、最多 4 张，避免每个推送目标都重复加载网页。官网改变 DOM 或资源地址时可能降级，需更新明确的站点规则，而不是扩大为任意域名访问。

## 验证

离线测试覆盖新闻正文提取、详情失败保留状态、同目标去重、截图失败文字回退、未知发送不重试、URL/DNS/图片边界及模块 epoch 变化。运行：

```sh
python -m unittest tests.modules.ff14.test_news tests.presentation.test_official_webpage tests.host.test_ff14_news
```

Host 集成测试按 CONTRIBUTING.md 先构建前端并准备独立 Host 合同源码；截图边界用合成 PNG 注入，不连接真实 IM。合并前在可启动沙箱 Chromium 的环境核对实际网页截图，不能把离线测试或之前的人工 demo 当作新实现的端到端验收。
