# FF14 国服新闻：版本更新与官网长截图

文件名保留早期 PR 链接；现实现使用桌面版，不再使用移动版。消息依次显示标题、分类、时间、正文摘录或修改差异、原文链接、官网文章截图。图片保留官网桌面排版，不重做成新闻卡片。

## 推送与版本

首次订阅建立当前列表基线，不补发历史新闻。之后新文章及已观察到的每个新内容版本各推送一次。连续观察到相同内容不会重复推送；A→B→A也属于两次内容修改，回退到A时会再次推送。持久修订序号用于区分每次已观察到的内容转移，同一次转移重试不重复。版本依据标题、分类、完整正文语义和正文图片/链接地址生成；发布时间、浏览量、列表顺序、HTML样式、脚本及常见跟踪参数不作为修改依据。原地址图片内容被替换、但地址和正文均未变时，目前不能识别。

新文章摘要取正文前几个有意义的句段，最多200字；更新摘要引用相较上一已观察版本新增、修改、删除的原文，最多260字。不使用LLM编造摘要，也不消耗模型额度。保留的正文差异片段有界，片段外发生变化时明确提示查看原文。时间标明官网发布时间，不把发现变化的时间伪称为官网修改时间。无法确认的官网分类保留分类编码，不猜测名称。

轮询先校验完整列表，再有界获取详情。详情每轮最多12条：优先新文章和标题/分类变更，刷新列表前4条，其余轮转。近期文章较快发现正文修改，较老文章可能需完整轮转后才发现；不能承诺捕获两次轮询之间出现又撤回的每次编辑。详情失败保留持久基线和进度，不提前将未取得的版本标记为已推送。已有仅按ID去重的状态静默学习正文基线，不重播旧文章。

版本历史、待发事件和已观察内容保存在现有数据库。完整列表最多32页/1600条，单轮最多45次请求，新闻源限制60次/分钟；不增加15分钟默认轮询频率。累计保留最多5000个ID，待发最多1600条，达到上限会保留原状态并报错，需维护处理；不会悄悄删除旧去重记录导致重播。发送沿用原有持久队列、资格校验和发送回执：明确失败按现有策略重试，结果不确定不盲目重发。截图是可选呈现，截图失败仍推送文字与链接并提示不可用，不另行补发图片。

## 截图与运行环境

仅复用运行 AstrBot 环境中**已有**的浏览器：Windows 标准安装位置的 Edge/Chrome，Linux 的 Chromium/Chrome（含常见系统与 Snap 路径），macOS 的应用目录 Chrome/Edge/Chromium。只检查明确的可执行文件，不读取个人浏览器配置、Cookie、历史或凭据，不操作用户已经打开的浏览器窗口。非标准安装路径目前不自动搜索。

可选的 Python 控制层是 Playwright。需要截图时，由管理员安装这个 Python 包即可，不会随安装包自动下载浏览器。完整插件 ZIP 附带 `requirements-news-screenshot.txt`；进入插件安装目录，用**运行 AstrBot 的同一个 Python/虚拟环境**执行（若 `python` 指向别处，请改为该解释器的完整路径）：

```sh
python -m pip install -r requirements-news-screenshot.txt
```

安装后可用同一解释器执行 `python -c "import playwright.async_api"` 检查导入；若 Host 缓存了导入状态，可重载插件。不要为此修改系统默认 Python 或安装到无关环境。控制层不列入基础 `requirements.txt`，不使用截图的环境无需承担其安装体积。

**不要运行 `playwright install`，本功能不需要下载 Playwright 自带浏览器。** 插件不安装浏览器、不自动安装控制层，也不使用远程截图服务。缺少 Playwright、没有可用已有浏览器、版本不兼容或沙箱不可用时，不输出图片，正常推送完整文字和原文链接。系统浏览器自动升级后兼容性仍需验证，不能保证所有版本均支持。

每次截图显式启动检测到的已有浏览器可执行文件，使用独立临时无头会话，完成后关闭；不连接用户现有会话，不关闭 TLS 验证或浏览器沙箱。最多尝试三个已存在的候选，每个启动预算8秒，大型更新笔记的总截图预算为120秒。

截图打开官网 `index.html`，采用1440像素桌面视口和DPR 1，截取 `.newsCont` 文章容器完整纵向范围，正文为 `.newcontbox`。保留标题、日期、正文与容器尾部；不修改网页排版。截图必须校验官网详情版本与待推送版本一致，避免旧摘要配新图片。等待正文图片完整加载；官网变化、超时或资源不可用时明确降级。

完整截图高不超过宽的30倍时优先一张；超过后，先在每张高为宽的10～20倍范围内求最少张数，再尽量均分。切点使用实际DOM的章节、内容块和行间边界，避开文字行及文章图片；不改变官网布局。若目标比例在安全边界下无法实现，可保留完整内容并放宽目标比例，仍不突破硬预算。不可分图片超限或不能完整分页时整组降级文字与原文链接，不只发送前几片。

图片保留原像素，优先无损PNG；大图在切分前尝试JPEG质量95、92、90、89、88，均关闭色度抽样，不缩小分辨率。截图专用本地预算为单片4,900,000字节、最多8片、合计24,000,000字节，单片最多4800万像素/43200像素高，原始浏览器PNG最多32MiB；全文最多240000像素高。超编码预算后沿安全边界重新规划完整文章，并在消息中说明本地预算导致分图。普通卡片的1MiB默认预算和拼图默认额度不变。这些是内部资源/传输预算，**不是QQ平台的真实上限**，像素预算也不是对整个浏览器进程RSS的保证。

为避免部分Chromium在一次超高截图中约每16384行重复栅格内容，内部按最多4096行的小区域截取，检查每块实际尺寸并按原像素逐行拼合，再编码成用户看到的一张或几张长图。内部小块不是发送分图，不丢行、不重叠；最终分图仍只采用前述内容边界和比例规则。

AstrBot的QQ官方适配器对这些图片使用base64 `file_data` 直传，OneBot/NapCat使用base64图片段。腾讯SDK的大文件分块上传额度不能直接用于前一条链路；公开资料未确认这两条链路统一的图片字节/像素硬上限。QQ官方适配器可能将多图拆成多条平台消息，因此同一次本地消息链不代表平台原子投递。最终接收、压缩与显示效果须分别进行获授权的真实平台验收；发送结果未知时仍不盲目补发。

## 网络和生命周期边界

仅识别带内容指纹的 `official_desktop_screenshot_v1` 可选标记和固定官网数字ID链接。普通链接不触发浏览器，不允许模块传入任意URL、选择器、脚本或浏览器参数。没有公开SDK结构修改。

浏览器不使用用户登录态、Cookie或配置目录；HTTP由匿名客户端执行，校验精确官网资源域名、HTTPS、端口和公网DNS结果，禁止重定向、内网、WebSocket与Service Worker。官网历史HTTP图片仅对已审查图片域名升级至HTTPS，不发HTTP请求。浏览器使用沙箱和不可用代理阻断自行直连。单次120秒、单资源4MiB、累计24MiB、200请求；截图串行。相同文章与版本的成功结果最多缓存4组、120秒、合计32MiB。大型更新笔记HTML正文最多50万字符，HTTP详情仍限200万字节；完整正文参与指纹，持久摘要片段仍限1024字符。

截图后继续检查模块epoch、订阅revision和发送claim。全部图片组件构建完成后只调用一次Host发送；任一组件构建失败整组退回完整文字，不发送半组。取消会关闭浏览器并向上传递。

## 验证状态

离线回归覆盖内容指纹、修改差异、持久状态迁移、失败重试、重复版本、详情轮转、完整分片、多图单次发送、UNKNOWN不重试及网络边界。Host集成使用真实Core、SQLite、调度和AstrBot适配器，但注入合成截图，不连接真实IM。

真实浏览器样例必须由对应候选的实际代码、运行环境已有浏览器和公开官网内容生成，并检查完整正文、图片、分图边界及退出状态。本地消息组件接收不能替代QQ官方和OneBot/NapCat的真实平台显示验收；具体候选和通过/失败范围以该次交付证据为准。
