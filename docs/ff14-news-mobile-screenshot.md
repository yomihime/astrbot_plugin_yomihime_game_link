# FF14 国服新闻：版本更新与官网长截图

文件名保留早期 PR 链接；现实现使用桌面版，不再使用移动版。消息依次显示标题、分类、时间、正文摘录或修改差异、原文链接、官网文章截图。图片保留官网桌面排版，不重做成新闻卡片。

## 推送与版本

首次订阅建立当前列表基线，不补发历史新闻。之后新文章及已观察到的每个新内容版本各推送一次。同一内容版本不会重复推送，包括内容改回以前已推送的版本。版本依据标题、分类、完整正文语义和正文图片/链接地址生成；发布时间、浏览量、列表顺序、HTML样式、脚本及常见跟踪参数不作为修改依据。原地址图片内容被替换、但地址和正文均未变时，目前不能识别。

新文章摘要取正文前几个有意义的句段，最多200字；更新摘要引用相较上一已观察版本新增、修改、删除的原文，最多260字。不使用LLM编造摘要，也不消耗模型额度。保留的正文差异片段有界，片段外发生变化时明确提示查看原文。时间标明官网发布时间，不把发现变化的时间伪称为官网修改时间。无法确认的官网分类保留分类编码，不猜测名称。

轮询先校验完整列表，再有界获取详情。详情每轮最多12条：优先新文章和标题/分类变更，刷新列表前4条，其余轮转。近期文章较快发现正文修改，较老文章可能需完整轮转后才发现；不能承诺捕获两次轮询之间出现又撤回的每次编辑。详情失败保留持久基线和进度，不提前将未取得的版本标记为已推送。已有仅按ID去重的状态静默学习正文基线，不重播旧文章。

版本历史、待发事件和已观察内容保存在现有数据库。完整列表最多32页/1600条，单轮最多45次请求，新闻源限制60次/分钟；不增加15分钟默认轮询频率。累计保留最多5000个ID和5000个版本，待发最多1600条，达到上限会保留原状态并报错，需维护处理；不会悄悄删除旧去重记录导致重播。发送沿用原有持久队列、资格校验和发送回执：明确失败按现有策略重试，结果不确定不盲目重发。截图是可选呈现，截图失败仍推送文字与链接并提示不可用，不另行补发图片。

## 截图与运行环境

在运行 AstrBot 的同一 Python 环境、同一系统用户下安装可选依赖：

```sh
python -m pip install -r requirements-news-screenshot.txt
python -m playwright install chromium
```

Linux 还需 Playwright 系统库和可用 Chromium 沙箱。插件不会自行下载浏览器、关闭TLS验证或关闭浏览器沙箱。缺少浏览器时仍可采集与推送文字。

截图打开官网 `index.html`，采用1440像素桌面视口和DPR 1，截取 `.newsCont` 文章容器完整纵向范围，正文为 `.newcontbox`。保留标题、日期、正文与容器尾部；不修改网页排版。截图必须校验官网详情版本与待推送版本一致，避免旧摘要配新图片。等待正文图片完整加载；官网变化、超时或资源不可用时明确降级。

正常长图尽量保留完整。超过单片5000像素高或1MiB时按连续纵向范围拆成有序图片，最多8片，放在**同一次消息链**内发送，不裁掉剩余内容。超过48000像素、片数或网络预算则整组降级文字，绝不只发前几片冒充全文。目标IM可能压缩图片，其最终展示仍需平台实测。

## 网络和生命周期边界

仅识别带内容指纹的 `official_desktop_screenshot_v1` 可选标记和固定官网数字ID链接。普通链接不触发浏览器，不允许模块传入任意URL、选择器、脚本或浏览器参数。没有公开SDK结构修改。

浏览器不使用用户登录态、Cookie或配置目录；HTTP由匿名客户端执行，校验精确官网资源域名、HTTPS、端口和公网DNS结果，禁止重定向、内网、WebSocket与Service Worker。官网历史HTTP图片仅对已审查图片域名升级至HTTPS，不发HTTP请求。浏览器使用沙箱和不可用代理阻断自行直连。单次35秒、单资源4MiB、累计24MiB、100请求；截图串行。相同文章与版本的成功结果最多缓存4组、120秒。

截图后继续检查模块epoch、订阅revision和发送claim。全部图片组件构建完成后只调用一次Host发送；任一组件构建失败整组退回完整文字，不发送半组。取消会关闭浏览器并向上传递。

离线回归覆盖内容指纹、修改差异、持久状态迁移、失败重试、重复版本、详情轮转、完整分片、多图单次发送、UNKNOWN不重试及网络边界。Host集成使用真实Core、SQLite、调度和AstrBot适配器，但注入合成截图，不连接真实IM。
