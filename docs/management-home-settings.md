# 管理页面与全局设置

唯一正式页面根为 `00-game-link`。首页提供模块入口；模块管理负责加载、恢复和受限普通配置维护；全局设置负责 Core 默认主题、字体、凭据存储与主密钥生命周期。模块主页、配置和辅助查询按受信 role 注册，详见 [前端合同](frontend-module-contract.md)。旧 shell/management 链接须从宿主详情重新打开，不转移、复用或续签旧 token。

普通设置当前值与草稿分开。保存携带精确 owner 与 revision/CAS，重复保存互斥。取消或放弃不写入；切页保留普通草稿、清除秘密草稿并围栏迟到响应。授权失效撤销秘密草稿、确认与旧回执，重新进入接受当前授权下的新读取。模块卸载或 epoch 改变后旧资源失效。

FF14 管理读取失败时清除当前上下文全部秘密草稿，包括已取得写回执后的读取失败；普通草稿保留。只有精确分类的授权拒绝显示授权失效，未知读取仍显示未确认；写回执不等于已核实快照，UNKNOWN 写入不自动重发。清理与回执处理先核当前 owner、运行身份和页面生命周期，旧请求不能清除新上下文的输入。

storage_security 描述私密边界，ready 描述加密库存就绪，configured 描述已保存，decryptable 描述可解密；这些均不代表上游成功。正常 ready 将恢复及全域重配收在高级区；旧数据可用时不要求重新填写业务凭据。恢复原密钥、全域重配、环境密钥转托管、迁移申请和清除凭据均绑定页面内确认；取消、切页、刷新或授权变化使确认失效。全域重配是逻辑失效，不宣称密码学擦除。

环境转托管复用当前可解密密钥，只提交 CAS，无需重填。环境变量由部署者移除后冷重启；刷新不会改变进程环境。旧布局先读取无路径、无秘密的迁移计划；计划说明源保留，不能称为已迁移。在线未知来源返回 requires_stopped_host；执行需完整停写证明。支持条件与离线工具见 [凭据存储](credential-storage.md)，不能手填密钥绕过 guard。

请求层 `management-requests.js`、合同校验 `management-contract.js`、状态控制 `management.js`、视图 `management-view.ts` 分开组织。Module 只消费独立公开服务。紧凑视觉和共用组件沿用 [UI规范](ui-guidelines.md)。离线测试、真实浏览器、Host、实际 IM 分别验收，代码支持不证明实例已安装或真实迁移成功。
